# gofs

参照 [sigoden/dufs](https://github.com/sigoden/dufs) 的设计，用 Go 重写的一个实用文件服务器，
并**额外实现了压缩包在线解压**。

单二进制、零第三方依赖（只用 Go 标准库）、内嵌前端，`go build` 出来直接就能跑。

## 特性

**基础能力（对齐 dufs）**Uninstaller

- 静态文件服务，目录浏览支持 HTML / JSON / 纯文本三种视图
- 深链 404 仍返回完整 HTML 外壳（HTTP 状态码保持 404），页面显示
  「目录不存在」与「回到根目录」，而不是一张裸文本错误页
- 大目录首屏分批渲染（200 行 / 批），底部按需追加；统计、全选与打包仍覆盖完整结果集；
  服务端同样分批读取目录项，只保留上限内的条目、其余仅计数，避免十万级目录的内存峰值
- 上传：拖拽上传、**整目录上传（保留层级）**、表单上传、`PUT` 直传、
  `X-Update-Range: append` 追加续传，
  并**默认把「传到根目录」的文件按 年/月/日 三级目录自动归档**
  （子目录原地放；可关闭、可自定义布局、可单次覆盖）；
  表单上传另有 1 GiB 硬上限（更大的文件走流式 `PUT`），归档后的真实落点会再做一次 ACL / 密钥 scope 复核
- 删除、新建目录（`MKCOL`）、**移动（单选或批量，用目录选择器挑目标）**、重命名（`MOVE`）、
  **批量重命名（查找替换、通配符/正则匹配、由示例生成正则，带实时预览与冲突跳过）**
- 递归搜索（`?q=`），搜索结果默认按相关度排序，也可切换名称 / 大小 / 修改时间；
  搜索条件写入地址栏：刷新、收藏、前进/后退都能恢复搜索现场；
  结果统计里显示当前搜索方式，模糊/精确命中会在文件名与所在路径里高亮
  （通配符 / 正则不猜命中范围，避免和服务端算得不一样）；
  仅完整路径命中（文件名和父路径都不含查询词）时，副行会标「路径命中」并高亮完整路径；
  客户端断开后遍历立即停止，不白占重任务名额
- 目录打包下载为 zip（可选压缩级别）：**不勾选就打包整个目录，
  勾选了就只打包所选**，选中的目录会连同内容一起递归打包
- 单文件下载支持 HTTP Range 断点续传、`?hash` 取 SHA-256
- 下载走**浏览器原生下载**（进度 / 暂停 / 续传都归浏览器的下载管理器），**复制文件链接**一键分享
- 基于路径的账号权限控制（`user:pass@/dir:rw,/dir2`），最长前缀匹配，
  页面走 **HTTP Basic 认证**（自带登录框，不弹浏览器原生对话框）
- **页面上的用户管理**：新建账号、按路径分配只读 / 读写权限、改密码、删除；
  密码只存 PBKDF2 摘要，落盘 `users.json`，与启动参数里的账号合并使用
- **账号自助改密**：任何登录用户（含启动参数账号）都能在顶栏「改密」，
  需再次验证当前密码；成功后全部会话、上传密钥与分享链接立即失效，
  新密码落盘后重启仍有效
- **默认只监听 `127.0.0.1`**（对外提供服务需显式 `--bind 0.0.0.0` 或具体网卡 IP）、
  隐藏路径 glob、访问路径前缀、CORS、HTTPS、unix socket
- **手机端交互适配**：触摸目标 ≥40px、无 hover 依赖、操作收进「更多」菜单、
  阻断 iOS 输入框自动缩放（详见下文）
- **键盘操作**：页面第一个 Tab 出现「跳到文件列表」，直达首行；进入列表后用
  ↑/↓/Home/End 移动，Enter 打开，Space 勾选；
  `Ctrl/⌘+A` 全选、`Delete` 删除、`F2` 重命名、`/` 搜索、`r` 刷新、`Esc` 清空选择；
  搜索框按 `↓` 进入首条结果（空结果则聚焦空状态动作），首条结果按 `↑` 回到搜索框；
  顶栏下拉与行内「更多」菜单打开即聚焦第一项，方向键移动，`Esc` 关闭并回到触发按钮
- **表头全选与选择态**：全选框在表头，批量选择时未选中行的行内操作自动弱化
- **排序首击方向**：名称首击升序，大小 / 修改时间首击降序，再点反向；
  搜索结果排序下拉使用同一口径
- **单击文件名直接打开**（目录进入 / 在线编辑 / 预览 / 下载）；
  多选仍由每行行首的复选框负责
- **登录密码可见切换**：登录框的密码框带显示 / 隐藏按钮
- **运行期服务设置**：登录后可在页面上直接**切换服务根目录**、
  **调整单文件上传上限**、**改访问路径前缀**、**改监听地址与端口**
  （监听项收在默认折叠的「高级网络设置」里，摘要显示当前端点）
  （热重绑，连接不中断），改完立刻生效、不用重启
  （换根受 `--no-root-switch` / `--root-allow` 约束，详见下文）
- **面向大文件与恶意使用的防护**：流式传输（内存与文件大小无关）、
  「无进展」超时（慢速大文件不被误杀）、断点续传、CSRF / 暴力破解 /
  慢速攻击 / 资源耗尽防护、存储型 XSS 与日志注入防护；
  **转发头默认不采信**（只认可信代理）、所有能验口令的接口共用失败限速
  （按「来源 + 账号」隔离，穿插成功请求无法清零别人的计数）、
  访问日志自动脱敏凭据（含上传密钥头）、软链逃逸与真实路径复核、编码 `..` 越权防护、
  大小写别名规范化、无鉴权部署的管理接口默认关闭、
  路径前缀注入与监听路径误删防护、可写部署的 index.html 默认沙箱化、
  删号 / 改密自动撤销该账号签发的密钥与分享、PBKDF2 并发闸门（详见下文）
- 自定义日志格式（`$remote_addr` `$status` `$http_user_agent` …）
- 可替换的自定义前端资源（`--assets`）
- 内嵌 SPA / index.html 渲染模式（`--render-index` / `--render-try-index` / `--render-spa`）；
  **可写部署**（上传 / 编辑 / 解压）里的 `index.html` 默认加 CSP sandbox，
  需要真正的同源应用时才显式 `--unsafe-index-html`

**在线预览**

- **单击**文件名直接看：**图片 / 视频 / 音频 / PDF / Office 文档**
  在弹窗里打开，而不是下载到本地再找程序
- **HTML 文件**：主操作是「打开」，在新标签页按页面加载（服务端 CSP
  `sandbox allow-scripts`：脚本可运行，但不透明源读不到本站数据）；
  编辑源码仍可从「更多 → 编辑」进入
- **Office 文档预览**（`docx` / `xlsx` / `pptx`）：自研解析，零第三方依赖，
  多工作表 / 多幻灯片用页签切换（见下文）
- 视频能不能播**先问浏览器**（`canPlayType`）：AVI / FLV 这类它解不开的容器
  不弹预览、直接下载，而不是给一个沉默的黑框；真播不了时给出具体原因和下载入口
- 文本类单击进编辑器（见下一节），压缩包点「内容」看清单，其余类型仍是下载
- 视频音频走 **Range 流式播放**，可以拖进度条、不占内存 ——
  登录下发的会话 cookie 让浏览器原生的媒体请求也能通过鉴权，**多大都能播**

**在线文本编辑**

- 支持 txt / markdown / html / json / xml / yaml / toml / ini / csv 以及各语言源码
- 单击文件名直接进编辑器；行号、Tab 缩进、回车自动续缩进、`Ctrl/⌘ + S` 保存
- **Markdown 渲染预览**（自研渲染器，支持标题/列表/表格/代码块/引用/任务列表）
- **HTML 沙箱预览**、**JSON 着色预览**、**XML 结构校验**
- **源码格式化**：JSON / XML / YAML / TOML / INI / conf / .config / .env
  都有「格式化」按钮（详见下文“格式化”）
- 保存时用**内容摘要做乐观锁**，文件被别人改过会提示而不是静默覆盖
- 保留原文件的 **CRLF/LF 换行风格**与 **UTF-8 BOM**，不会把整份文件的换行都改掉
- 二进制文件、超大文件、UTF-16 编码一律拒绝，避免改坏文件

**上传密钥**

- 给脚本 / 第三方的最小权限凭证：**只能上传**，不能读、删、改、解压
- 可限定目标目录、可设有效期（1 小时 ~ 永不过期）、可随时撤销
- 创建后给出四段可直接复制的用法示例（一键脚本 / 请求头 / 查询参数 / 保存脚本），
  一键脚本只复制 `bash <(curl …)` 本身，文件参数另行展示
- 列表支持逐条勾选或「全选」后**批量撤销**，有失败项时汇总提示
- 明文只在创建时显示一次，服务端只存 SHA-256 摘要
- 创建者的权限是上限：签发时检查调用者对该目录的写权限，**每次使用**时还会
  按创建者当前 ACL 复核目标路径 —— 签发时 `/docs` 可写，不等于之后仍能写
  `/docs/finance`（更具体的只读规则同样生效）

**在线解压（本项目的增量）**

- 支持 `zip` / `tar` / `tar.gz` / `tgz` / `gz`，按文件头嗅探而非只看扩展名
- **内容预览**：不发请求落盘，直接在网页里列出压缩包清单，并可流式取出单个文件
- **在线解压**：解压到服务端磁盘，通过 SSE 实时推送进度（当前条目 / 文件数 / 字节数 / 跳过数）
- 安全防护：Zip Slip、软链逃逸、解压炸弹、权限位提权
- 目录列表里自动给压缩包打「可解压」标记；有解压权限时点标记可直接看清单

## 快速开始

> 默认只监听 `127.0.0.1`。需要从局域网或容器外访问时，显式加
> `-b 0.0.0.0`（或具体网卡 IP）；无鉴权时请先确认这确实是你要的暴露范围。

```bash
# 构建（需要 Go 1.25+：os.Root 的安全 Rename/RemoveAll 用于防 TOCTOU）
go build -o gofs ./cmd/gofs

# 以只读模式服务当前目录
./gofs

# 服务指定目录，并开放全部操作（含在线解压）
./gofs -A ./data

# 同时服务多个目录：第一个是主目录（服务在 /），其余挂在名字下 → /backup/…
./gofs -A ./data ./backup /srv/projects

# 明确只开解压，不开上传删除
./gofs --allow-extract ./uploads

# 需要账号密码：admin 全目录读写，guest 只读
./gofs -a admin:123@/:rw -a guest:guest@/ -A ./data

# 只开在线编辑，不开上传删除
./gofs --allow-edit ./docs

# 完整示例：鉴权 + 编辑 + 解压 + 密钥
./gofs -A -a admin:123@/:rw -b 127.0.0.1 -p 5000 ./data
```

启动后会打印当前生效的配置：

```
gofs 0.1.0
  监听      : http://127.0.0.1:5000
  服务目录  : /home/me/data
  权限      : upload=on edit=on delete=on search=on archive=on extract=on keys=on
  鉴权      : 已启用（1 条规则），页面使用 Basic 认证
  上传密钥  : /home/me/.config/gofs/keys.json
  用户表    : /home/me/.config/gofs/users.json
  设置文件  : /home/me/.config/gofs/settings.json
  防护      : 上传≤10GiB  打包≤200000条/50GiB  目录≤20000条  并发512  无进展超时2m0s  跨站校验on
```

启动后访问 `http://127.0.0.1:5000`。**有管理能力**的账号（对服务根有读写权限，
或能管理密钥/用户）会在顶栏看到 **「设置」** —— 换数据目录、临时放宽上传上限、
管密钥与用户都不需要重启（见「服务设置（运行期）」）。
⚠️ **未启用鉴权时管理面默认关闭**，页面上不出现「设置」：
无鉴权意味着任何能连上端口的人都能访问，而管理接口能挂载任意目录、换根、
改监听地址。确实需要这种用法时显式加 `--allow-anonymous-admin`。

## 命令行选项

```
gofs [选项] [serve-path ...]

  [serve-path ...]           要服务的路径，默认 "."。第一个是主目录（服务在 /），
                             其余挂在各自名字下（/backup/…）；也可以在页面上
                             运行期增删。重名自动加后缀，互相嵌套会被拒绝

  -b, --bind <addrs>         监听地址或 unix socket，默认 127.0.0.1。
                             对外提供服务请显式 --bind 0.0.0.0（或具体网卡 IP）；
                             socket 路径上若已有普通文件/目录/软链会拒绝启动，
                             不会删除它们
  -p, --port <port>          监听端口，默认 5000
      --path-prefix <path>   访问路径前缀。不能包含空白、控制字符、? # " ' < > \
                             或连续斜杠 //，也不能有 . / .. 段
      --hidden <value>       目录列表中隐藏的路径 glob，例如 tmp,*.log
  -a, --auth <rules>         鉴权规则，例如 user:pass@/dir1:rw,/dir2
  -A, --allow-all            允许所有操作
      --allow-upload         允许上传
      --allow-edit           允许在线编辑文本文件（默认跟随 --allow-upload）
      --edit-max-size <n>    在线编辑允许打开的最大文件尺寸，默认 2MiB
      --allow-keys           允许管理上传密钥（默认跟随 --allow-upload）
      --allow-share          允许只读实例（无上传/编辑/解压）创建分享链接
      --key-file <path>      上传密钥存储路径，默认 <用户配置目录>/gofs/keys.json；
                             置空则只保存在内存中
      --user-file <path>     用户表存储路径，默认 <用户配置目录>/gofs/users.json；
                             置空则只保存在内存中
      --title <text>         站点标题（浏览器标签页与顶栏品牌名），默认 gofs。
                             管理员也能在「设置 → 常规」里改，改完会落盘
      --settings-file <path> 运行期设置的存储路径，默认 <用户配置目录>/gofs/settings.json；
                             置空则只保存在内存中
      --no-user-manage       禁止在页面上增删改用户（账号只能由 -a 定义）
      --allow-delete         允许删除
      --allow-search         允许搜索
      --allow-archive        允许目录打包为 zip 下载
      --allow-extract        允许在线解压压缩包
      --allow-symlink        允许符号链接指向根目录之外
      --enable-cors          开启 CORS
      --render-index         目录下 index.html 作为首页，不存在返回 404
      --render-try-index     优先 index.html，无则目录列表
      --render-spa           SPA 模式，未命中回退 index.html
      --unsafe-index-html    可写部署（上传 / 编辑 / 解压）中的 index.html
                             默认加 CSP sandbox；加此项才允许它以同源方式执行
      --assets <path>        自定义前端资源目录（默认禁止位于服务根内）
      --unsafe-assets-in-root
                             允许 assets 位于服务根内（开发用，可能导致同源 XSS）
      --cookie-secure        强制会话/分享 Cookie 带 Secure（反代终止 TLS 时用）
      --log-format <format>  自定义 HTTP 日志格式（none 可关闭）
      --log-file <file>      日志文件
      --compress <level>     打包压缩级别：none/low/medium/high，默认 low
      --upload-date-layout <layout>
                             上传时自动归档的日期目录布局（Go 时间布局字面量），
                             默认 "2006/01/02"，即按 年/月/日 建三级目录；
                             置空（--upload-date-layout=""）则关闭
                             ★ 只对「直接传到服务根目录」的上传生效：
                               /pic.jpg      → /2026/09/28/pic.jpg
                               /sub/pic.jpg  → /sub/pic.jpg（子目录原地放）
                             单次可覆盖：?dated=0 跳过、?dated=1 强制归档
      --no-upload-dated      关闭上传按日期自动归档
      --tls-cert <path>      HTTPS 证书
      --tls-key <path>       HTTPS 私钥
      --extract-max-total <n> 解压写出字节上限，默认 10GiB
      --extract-max-files <n> 解压文件数上限，默认 100000
      --extract-max-ratio <n> 单文件压缩比上限，默认 200
  -V, --version              打印版本
  -h, --help                 打印帮助
```

防护选项（默认即为较安全的取值，一般无需调整）：

```
      --upload-max-size <n>  单次上传的最大字节数，默认 10GiB；0 表示不限制
                             （登录后也可以在页面的「服务设置」里改）
                             ⚠️ multipart 表单上传另有 1GiB 硬上限（临时文件），
                             更大的文件请用流式 PUT
      --upload-read-timeout <d>
                             上传「连续多久没有进展」就断开，默认 2m
      --download-timeout <d> 下载「连续多久没有进展」就断开，默认 2m；0 表示不限制
      --list-max-entries <n> 单次目录列举最多返回多少条，默认 20000
      --archive-max-items <n> 单次打包的条目数上限，默认 200000
      --archive-max-bytes <n> 单次打包的原始字节上限，默认 50GiB
      --max-concurrent <n>   同时处理的请求数上限，默认 512；0 表示不限制
      --max-concurrent-jobs <n>
                             同时进行的重任务数上限，默认 64
                             （上传 / 解压 / 打包 / Office 预览 / ?hash 摘要）
      --auth-fail-limit <n>  同一来源+账号认证失败多少次后临时封禁，默认 10
      --auth-fail-window <d> 认证失败的统计窗口与封禁时长，默认 5m
      --trusted-proxies <ips>
                             可信反向代理地址（IP / CIDR，逗号分隔）。
                             只有直连对端在列表内时才采信 X-Forwarded-For /
                             X-Real-IP / X-Forwarded-Proto；默认不信任任何转发头
      --max-header-bytes <n> 请求行+请求头允许的最大字节数，默认 64KiB
      --max-name-bytes <n>   允许的单个文件名最大字节数，默认 255
      --hash-max-size <n>    允许计算 ?hash 摘要的最大文件字节数，默认 512MiB
      --no-csrf-protect      关闭写操作的跨站来源校验
      --no-html-sandbox      关闭 HTML/SVG/XML 的 CSP sandbox
      --no-root-switch       禁止登录后在页面上切换服务根目录
      --root-allow <prefix>  允许把服务根目录切换到的路径前缀，可重复指定
      --allow-anonymous-admin
                             未启用鉴权时仍允许通过 HTTP 管理接口修改服务设置。
                             默认关闭：无鉴权时任何能连上端口的人都不应能
                             挂载任意目录、切换服务根或修改监听地址
```

所有选项都可以用 `GOFS_` 前缀的环境变量设置，例如
`GOFS_PORT=8080 GOFS_ALLOW_EXTRACT=true ./gofs ./data`。
多条鉴权规则在环境变量里用 `|` 分隔：

```bash
GOFS_AUTH='admin:123@/:rw|guest:guest@/' ./gofs ./data
```

## 移动文件或文件夹

行操作里的**「移动」**、或者勾选若干项之后的**「移动所选」**，都会打开一个
**目录选择器**：从当前目录出发，点目录进去、点「上级目录」往回退，
选好目标点「移到这里」。不用手打路径。

几个约定：

- **正在被移动的目录不会成为候选**。把 `/a` 移进 `/a/b` 会把整棵树搬进
  它自己里面 —— 选择器里那一项是禁用的，服务端也会再挡一道
  （`400 不能把目录移动到它自己里面`）。两边都做是有意的：
  界面让人走不到那条死路，服务端保证绕不过去。
- **目标同名已存在时不覆盖**（`Overwrite: F`），会报「目标同名已存在（未覆盖）」，
  源文件原样留在原地。静默覆盖用户数据比失败更糟。
- **一次移动多项**时逐个发请求，结束后统一报「成功 / 已在该目录 / 冲突 / 失败」
  各多少项；有失败会带出第一条原因。
- 目标必须在服务根之内（越界会明确报「超出服务范围」，与「路径非法」区分开）。
- **跨设备移动（回退到「复制 + 删除」）默认不跟随软链**：软链条目会被跳过，
  而不是把根外文件的内容复制进来，也不会沿着「软链指回上级目录」无限递归。
  显式 `--allow-symlink` 的部署保持旧语义（复制软链指向的内容）。

协议层面就是 WebDAV 风格的 `MOVE` + `Destination` 头，所以脚本也能直接用：

```bash
curl -X MOVE -u user:pass \
  -H "Destination: http://host/archive/a.txt" \
  http://host/a.txt
```

## 批量重命名

行操作里的**「重命名」**一次改一项；要改一批同款的名字（`IMG_001.JPG`、
`IMG_002.JPG`…）就勾选它们，点工具栏的**「重命名所选」**。

弹窗里只有一件事要做：填**查找内容**与**替换为**，下面的表格**边打边显示每一项
的新名字** —— 改动的那一段高亮，剩下的一目了然。

- **多种查法**：默认按字面量、不区分大小写（输入「img」也能命中 `IMG_001.JPG`）；
  勾上「通配符」后，`*` 匹配任意字符、`?` 匹配单个字符，**整段名称必须匹配**
  （所以 `*.log` 不会顺带命中 `a.log.bak`），「替换为」里可用 `$1` 引用第 1 个
  `*`/`?` 匹配到的内容、`$&` 引用整段匹配；勾上「正则表达式」后支持 `$1`、`$&`
  这类反向引用（写错正则会当场标红并禁用提交）。通配符与正则互斥，勾一个会取消
  另一个。两种表达式模式下「替换为」里的 `$&`、`$1` 都有特殊含义，要填字面的
  `$` 就写成 `$$`。例如查找 `(web)(\d+)`、替换 `$1_site_$2`，`web01` →
  `web_site_01`；查找 `\d+`、替换 `[$&]`，`web01` → `web[01]`。
  通配符同样受**作用范围**约束：默认只作用于主名，`*.log` 这类写法要切到
  「名称和扩展名」才能命中。
- **作用范围**默认是**名称（不含扩展名）**：改错扩展名的代价是文件变得打不开，
  而真需要改扩展名时切一下只是多一次点击。
- **由示例生成正则**：弹窗右侧的面板会预填第一个选中项的名字。在示例名里选中
  要匹配的片段（如 `web01` 里的 `01`），下面会给出 `01`、`\d{2}`、`01$`、
  `\d{2}$` 等候选并标注「命中 N/M」；点一下就填入「查找内容」、自动勾选
  「正则表达式」，预览随即刷新。匹配片段也可以直接手填（手机上拖选不便时更实用）。
  锚定按**作用范围**的口径算：范围是「名称（不含扩展名）」时，`web01.log` 里选
  `01` 得到的是主名末尾的 `01$`；选到扩展名上会提示切换范围。候选只是起点，
  下面的逐行预览才是准绳。生成器完全在本地计算，不额外请求，也不记住示例与片段。
- **冲突项自动跳过**：目标同名已存在、与本次的其它项重名、名称非法或超长，都会
  标红、取消勾选并写明原因，**不覆盖任何已有文件**。其余项照常改名。
- **目标位置也要有写权限**：源路径、目标路径、以及软链解析后的真实路径都按
  ACL 复核；改名整个目录时还会逐个比较后代在新位置的权限，不允许把它们
  搬进一条更宽的规则里。
- **一次提交，要么全改要么全不动**。服务端先整批校验，任一不合格就整批拒掉并逐项
  说明原因 —— 不会出现「改了前 4 项、第 5 项失败」那种改了一半的目录。
- 重命名之后**保持选中**（选中状态跟着新名字走），方便接着做下一步。
- 只改**同目录内的名字**，不搬目录；要挪地方用「移动所选」。

界面上不好表达的情形（互换名字 `A→B` 且 `B→A`、链式让位 `A→B` 同时 `B→C`）
协议层也是对的，脚本可以直接调：

```bash
# a1.txt → b1.txt、b2.txt → a2.txt（一次请求，一起成功或一起失败）
curl -X POST http://host/fs/rename-batch \
  -H 'Content-Type: application/json' \
  -u user:pass \
  -d '{"items":[{"path":"/a1.txt","name":"b1.txt"},
                {"path":"/docs/b2.txt","name":"a2.txt"}]}'
```

成功时返回 `{"ok":true,"renamed":[{"from":"/a1.txt","to":"/b1.txt"}],"skipped":[…]}`；
被拒时返回 `400` 与 `{"message":"有 N 项无法重命名，未做任何改动","errors":[{"path":…,"reason":…}]}`
（此时**磁盘上什么都没动**）。名称上限、路径权限、站点根保护都与单条 `MOVE` 同一套判定。

## Office 文档预览

`docx` / `xlsx` / `pptx` 单击文件名直接在弹窗里读，不用下载再用 Word 打开。

**浏览器不认这些格式，而本项目坚持零第三方依赖** —— 连 Markdown 渲染器都是
自研的。所以这里的做法是：服务端用标准库（`archive/zip` + `encoding/xml`）
把文档解成**结构化内容**，前端再渲染。

```bash
# 服务端返回的是中性模型，不是 HTML
curl -u user:pass "http://host/fs/office?path=/报告.docx"
{"format":"docx","parts":[{"blocks":[{"type":"heading","level":1,
 "runs":[{"t":"季度经营报告"}]}, ...]}]}
```

| 格式 | 能读到 | 读不到 |
| --- | --- | --- |
| `docx` | 标题层级、段落、**加粗/斜体/下划线**、列表、表格（含横向合并） | 分页、字体、颜色、图片、图表、批注、页眉页脚 |
| `xlsx` | 全部工作表、单元格值、共享字符串、**空行空列按原位置补齐** | 公式结果、单元格格式、图表 |
| `pptx` | 每张幻灯片的文字 | 版式、图片、图表、动画、备注 |

一句话：**内容读得到，版面不还原**。要还原版面得引入排版引擎（LibreOffice）
或几百 KB 的第三方 JS 库，都与本项目「单二进制、零依赖」的取舍相悖。

老的 `.doc` / `.xls` / `.ppt`（Office 97-2003）**不支持**：那是 OLE2 复合文档，
二进制格式，标准库解不了。它们仍然走下载。

### 为什么不是「服务端渲染成 HTML」

因为那样要处处记得转义，漏一处就是一个 XSS。这里服务端只产出数据
（块、表格、文本片段），前端一律用 `textContent` 与 `createElement` 渲染 ——
**数据与标记在架构上就是分开的**，不依赖过滤是否周全。
响应是 `application/json` + `nosniff`，浏览器不会把它当页面解析。

### 安全上的几道上限

OOXML 是用户上传的内容，里面的数字全都不可信：

- **单条目**解压后最多读 32 MiB，**总量** 64 MiB —— 用 `io.LimitReader` 卡，
  而不是先读完再判长度（后者意味着内存已经分配出去了，攻击者已经赢了）；
- 绝不采信 zip 目录里写的 `UncompressedSize64`，那是可以随便填的声明值；
- 条目数、部分数（工作表/幻灯片）、行数、列数都有上限，超了就截断并在
  页面上说明；
- **XML 嵌套深度**最多 512 层、单次解析最多 200 万个 token：`encoding/xml`
  每遇到一个开始标签都会在内部栈上压一个节点，解析栈占用会随深度放大几十倍，
  只限制字节数挡不住。超限的 docx 直接拒绝，xlsx/pptx 停止解析并标记截断；
- 单段落文本片段、表格列数、待应用样式标记、解析提示条数也各有上限，超出即截断；
- **输出文本总量** 8 MiB、**单元格总数** 20 万：XLSX 的共享字符串会被成千上万个
  单元格引用，只限制单段长度挡不住整份 JSON 在序列化时被放大；超限后标记截断并
  停止继续填充；
- **打开前先做有界 EOCD 预检**：中央目录声明超过 2 万条（与解析器的
  `maxEntries` 一致）或 64 MiB 直接 `413`，Zip64 一律拒绝 ——
  `zip.NewReader` 会先解析整个中央目录，不能等解析到一半再发现太大；
- **整个文件**不超过运行时上传上限（未配置上限时兜底 512 MiB）；
- 解析与其它重任务共用 `--max-concurrent-jobs` 名额，不能靠并发预览
  绕过。

另外 Go 的 `encoding/xml` **不做 DTD 实体展开**，所以 XXE（`<!ENTITY xxe
SYSTEM "file:///etc/passwd">`）在这里天然不成立 —— 这是不用第三方 XML 库的
一个附带好处，有测试钉着。

⚠️ 预览等同于读取文件内容，所以 `/fs/office` 会按路径做**读权限**校验，
并按软链解析后的真实路径再复核一次。

预览弹窗支持左右方向键或两侧按钮在当前目录的可预览文件间切换，并显示

实际大小下可按 − / + 调整倍率、点百分比回到 100%，超出部分可滚动；右下角
同时显示原始尺寸与文件大小。

### 视频要看浏览器认不认

能播放哪些容器**由浏览器决定**，不由 gofs 决定。所以预览前会先问一次
`<video>.canPlayType()`，播不了的不弹预览、直接下载 —— 弹了也只是一个
永不播放的黑框。

实测（Chrome）：

| 容器 | 结果 |
| --- | --- |
| `mp4` `m4v` `webm` `ogv` `mov` | 预览播放 |
| `avi` `flv` | 不预览，直接下载（浏览器解不开这两个容器） |
| `mkv` | 交给浏览器裁决：Chrome 能放 H.264 的，Safari 通常不行 |

`mov` 是个例外：`canPlayType('video/quicktime')` 在 Chrome 里返回**空**，
但同一个 H.264 的 .mov 实际播得好好的。所以这几个已知能播的容器走白名单，
其余才交给 `canPlayType` —— 只信它会把能播的判成不能播。

真播不了时（编码不支持如 H.265/ProRes、文件损坏、网络中断），
播放器会被换成一句**具体**的说明加一个「下载文件」按钮。
没有这段的话，失败就是一个沉默的黑框，用户只能得出「不能播放」，
却分不清是格式、损坏还是网络。

### 多大都能播：会话 cookie

预览**直接用文件的原始地址**，视频音频走 Range 流式播放，能拖进度条，
内存占用与文件大小无关 —— 4.6 GiB 的片子也一样。

这靠的是登录时下发的一个 **HttpOnly 会话 cookie**。在此之前的做法是
先 `fetch` 成 blob 再喂给标签，因为鉴权靠 `Authorization` 头，
而浏览器替 `<img>` / `<video>` 发请求时**不会**带这个头；
可 blob 意味着整个文件进内存，所以那时只能设一条 256 MiB 的线硬拦。

| | |
| --- | --- |
| 有效性 | 服务端会话表，30 天绝对寿命 + 7 天空闲上限 |
| 单账号上限 | 16 个；超出时替换该账号最旧的会话，单个账号占不满整张表 |
| 撤销 | 登出、**改密码**、删账号都会立即作废已有会话 |
| 名称 | 默认 `gofs_sid`；HTTPS 根路径下优先 `__Host-gofs_sid`（不允许 Domain，子域无法覆盖）。从旧版本升级到 HTTPS 根路径部署需重新登录一次 |
| 浏览器寿命 | 勾选「保持登录」30 天；否则是浏览器会话级 Cookie（服务端会话本身仍按 30 天/7 天空闲管理） |
| HttpOnly | JS 读不到 token，XSS 偷不走 |
| SameSite=Lax | 跨站子资源请求不带它，挡住借已登录身份读私有文件那类攻击 |
| Secure | HTTPS 下附加（含可信代理声明的 HTTPS），纯 HTTP 部署照常工作；反代终止 TLS 且未配置可信代理时用 `--cookie-secure` 强制附加 |
| 路径 | 跟随 `--path-prefix`，前缀部署下依然生效 |

登录接口（`GET/POST /fs/auth`）与其它接口一样受认证失败限速约束
（`--auth-fail-limit` / `--auth-fail-window`）—— 它会发一张 30 天有效的通行证，
不限速等于把口令交给字典攻击。

计数按「来源 + 凭据类别 + 账号」隔离：只按来源统计的话，持有任意合法账号的人
可以穿插自己的成功请求，把针对别人账号的失败记录清零；不分类别的话，几个坏
Cookie 就能把同一 IP 上的有效会话和匿名访问一起锁死。成功登录只清掉本类别、
本账号的计数；失败记录表的键是固定长度摘要、并有 65536 条硬上限，用户名再长
也不会撑大内存，淘汰时也会跳过仍在封禁期的记录，避免攻击者灌满表把针对自己的
封禁挤掉。

⚠️ **不是所有 `GET /fs/auth` 都会下发会话 cookie**：查询串凭据一律不建立会话；
GET + Basic 也只有带 `X-Gofs-Ajax: 1`（应用自己的登录框）时才建立。否则
`https://user:pass@host/fs/auth` 这类顶层导航会让受害者静默登录到攻击者账号
（登录 CSRF）。需要 cookie 的非浏览器客户端请走 `POST /fs/auth`，或带
`Authorization` 头。

跨站请求里的查询串凭据（`?user=&pass=`）会被直接忽略，且不计入认证失败封禁 ——
否则攻击页面可以用十个 `<img src="…?user=admin&pass=wrong">` 把受害者出口 IP
上的 admin 账号打进封禁名单。

登出走 `DELETE /fs/auth`：cookie 是 HttpOnly 的，JS 删不掉，
必须由服务端撤销会话再清 cookie，否则「退出登录」只是把界面上的名字抹掉。

服务端仍支持**同源**请求用 `?user=&pass=` 传凭据（方便媒体标签与脚本直连），
跨站请求会忽略它。前端页面自己**没有采用**这种写法：那会把密码写进 URL，
访问日志、浏览器历史、Referer 全都会留下；页面登录请用 `POST /fs/auth`
或 `Authorization` 头。

### 脚本型文件不会被内嵌预览

只有 PDF 走 `<iframe>`。HTML / SVG / XML 绝不放进应用内的 iframe ——
那样等于绕开服务端给这几类文件加的 CSP sandbox，
把「上传一个带脚本的页面 → 诱导管理员打开」这条路重新打开（见「安全与防护」）。

SVG 走 `<img>`：图片上下文里脚本不会执行，是安全的。
HTML 的「打开」是把文件 URL 交给**新标签页**，由服务端按普通 HTML 响应返回，
并附带 `sandbox allow-scripts`：脚本可以运行，但文档在不透明源里，
读不到本站 cookie / 本地存储，也发不出同源请求。要连脚本和同源能力都完整保留，
部署时需要显式 `--no-html-sandbox`，这是部署方的安全决策。
HTML 的源码仍可从行内「更多 → 编辑」进入编辑器修改。

xml / svg / toml / ini / conf / config / properties / env / csv / tsv / sql / sh / bash /

tf / hcl / proto / graphql … 以及 `Makefile` `Dockerfile` `.gitignore` `.env` 等无扩展名文件。

判定分两步：

1. **列表阶段只看文件名**，不读内容——列举目录时不该产生大量磁盘 IO；
2. **打开时再做内容嗅探**：含 NUL 字节或大量非法 UTF-8 一律判定为二进制并拒绝，
   防止编辑器把图片当文本打开后再保存，把文件彻底毁掉。

### 编辑器能力

- 行号、`Tab` 缩进（多行选区整体缩进 / 反缩进）、回车自动延续上一行缩进
- `Ctrl/⌘ + S` 保存，`Esc` 关闭（有未保存改动会二次确认）
- 状态栏显示行数、字符数、换行风格、BOM、文件大小与修改状态
- JSON / XML / YAML / TOML / INI / conf / config / .env 提供源码格式化；
  YAML 的 `|` / `>` 块标量会保留内容与空白，跨行引号 / 非块式多行标量
  仍会拒绝格式化，而不是冒险改坏内容
- 超过 5000 行自动关闭行号渲染，避免大文件把 DOM 撑爆

### 预览

| 类型 | 预览方式 |
| --- | --- |
| Markdown | 自研渲染器，支持标题 / **粗体** / *斜体* / 行内代码 / 围栏代码块 / 列表 / 任务列表 / 表格 / 引用 / 分隔线 / 链接 / 图片 |
| HTML | `iframe sandbox=""`（**禁止脚本、禁止同源**，否则预览自己上传的 HTML 会让其中的脚本拿到凭据） |
| JSON | 格式化 + 语法着色，非法时指出解析错误 |
| XML | `DOMParser` 结构校验，非法时指出出错位置 |

Markdown 渲染前先对所有文本做 HTML 转义，链接还会过滤 `javascript:` / `data:` 协议。

### 格式化

编辑器工具栏里的「格式化」**直接改写正文**（会进入未保存状态，仍可用撤销/保存）：

| 格式 | 行为 |
| --- | --- |
| JSON | `JSON.parse` + 2 空格缩进；非法 JSON 只报错不改内容 |
| XML | `DOMParser` 校验后按层级缩进；混合内容保留原内部形态 |
| YAML | 保守整理块式配置的缩进（统一 2 空格）；`|` / `>` 块标量的内容与行尾空白原样保留、只随块头整体平移；跨行引号、Tab 缩进或非块式多行标量时拒绝格式化 |
| TOML | 统一 section 头与 `key = value` 空白；多行 `"""` / `'''` 内容原样保留 |
| INI / conf / config | 统一 section 头与 `key = value`；缩进续行原样保留 |
| .env | 统一成 `KEY=value`，保留 `export` 前缀、引号与行内注释 |

格式化不改变换行风格与 BOM：保存时仍按原文件的 CRLF/LF 和 BOM 写回。

### 安全与一致性

**乐观锁用内容摘要而非时间戳。** 打开文件时返回 `hash`（SHA-256 前 16 位），
保存时带上；服务端比对当前内容摘要，不一致返回 `409` 并附带 `current_hash`，
由用户决定是否强制覆盖。用时间戳会在「同一毫秒内两次保存」时误判。

**换行风格会被保留。** 浏览器的 `<textarea>` 提交时会把 CRLF 规范化成 LF，
若直接写回，Windows 换行文件的每一行都会变，在 git diff 里表现为整个文件被改。
服务端检测原文件风格并在写回时还原。

**BOM 会被保留。** 读取时剥离 UTF-8 BOM 交给编辑器，写回时重新加上。
UTF-16 编码的文件直接拒绝编辑（客户端无法正确处理）。

**写入是原子的。** 先写同目录临时文件再 `rename`，不会出现写到一半的残缺文件。

### API

```bash
# 读取
curl -u admin:123 'http://127.0.0.1:5000/fs/text?path=/README.md'

# 保存（base_hash 来自读取响应）
curl -u admin:123 -X PUT http://127.0.0.1:5000/fs/text \
  -H 'Content-Type: application/json' \
  -d '{"path":"/README.md","content":"# 新内容\n","base_hash":"3bca2438f174ef9a"}'

# 冲突时强制覆盖
curl -u admin:123 -X PUT http://127.0.0.1:5000/fs/text \
  -H 'Content-Type: application/json' \

```

## 上传密钥

给脚本或第三方一个**只能上传**的凭证，不用交出账号密码。

登录后点顶栏**「设置」→「密钥」**标签即可管理。密钥的能力被刻意收得很窄：

| 能做什么 | 不能做什么 |
| --- | --- |
| `PUT` / `POST` 上传文件到指定目录 | 读取目录列表或文件内容 |
| 受日期归档规则约束 | 删除、重命名、新建目录 |
| — | 解压压缩包、在线编辑、管理其它密钥 |

最后一条尤其重要：**密钥不能用来管理密钥**，否则一把只能传文件的凭证
就能给自己签发新凭证，等于权限提升。**分享令牌同样不能签发新密钥/分享**：
创建接口的范围授权只按账号凭据计算，一条临时的可读写分享换不来一把永久密钥。

### 一键脚本上传

创建密钥后，页面上会给一段**直接能跑**的命令 —— 密钥和服务地址都已填好，
不用存文件、不用改任何地方：

```bash
bash <(curl -sS "https://<服务地址>/up?key=<密钥>") 文件或目录... [目标子目录]
```

生成密钥的弹窗里，四段用法示例（一键脚本 / 请求头 / 查询参数 / 保存脚本）
各自带一个**「复制」按钮**。一键脚本那条只复制 `bash <(curl …)` 命令本身，
文件/目录参数以「示例」另起一行展示，不会跟着进剪贴板。

传一个目录时**连子目录层级一起传**（顶层目录名也保留）：

```bash
# 本地 src/apps/web/index.html  →  服务端 <目标>/src/apps/web/index.html
bash <(curl -sS "…/up?key=…") src
bash <(curl -sS "…/up?key=…") src docs      # 放进 docs/ 子目录
bash <(curl -sS "…/up?key=…") a.txt b/ c/   # 一次传多个
```

也可以先存成文件用：

```bash
curl -sSLo gofs-up.sh "https://<服务地址>/up?key=<密钥>"
chmod +x gofs-up.sh
./gofs-up.sh 文件或目录...
```

脚本只用 `bash` 和 `curl`，拿到就能跑。它做的事就是逐个文件发
`multipart/form-data` 请求：

- 目录层级靠 `path` 表单字段保留 —— 单靠文件名不行，
  服务端会把多部分文件名压平到它的基本名，所以别指望 `-F "file=@a/b/c.txt"`
  能自己带上 `a/b/`；
- 最后一个参数若不是已存在的路径，就当作目标子目录；
- **HTTP → HTTPS 自动切换**：反代终止 TLS 且没把 `X-Forwarded-Proto`
  传给服务端时，生成的地址可能是 `http://`。脚本会先发一个**不带密钥**的
  `HEAD` 探测，被 3xx 跳到 https 就把同一路径换协议重发；探测没命中时，
  上传请求本身的 3xx 也会触发同样的兜底。重试**不跟随 `Location`**
  （有的反代会丢掉路径与查询串），避免文件被传到根目录或别的范围。
  3xx 不再被当成成功 —— 这正是「脚本说传完了、服务器上却没有文件」的来源；
- 结束打印成功/失败计数，有失败时退出码非 0，方便放进 CI。

⚠️ **一个容易意外的点**：单个文件直接传到服务根目录时会走**日期归档**
（默认 `--upload-date-layout=2006/01/02`），也就是落到 `/2026/09/30/` 下；
而传目录、或指定了目标子目录时不会（归档只对「直接传到根目录」生效，
与 `PUT` 上传的规则一致）。想关掉就加一个 `--upload-date-layout=""` 启动，
或者让脚本带上目标子目录。

脚本端点 `GET /up?key=<密钥>` 用**密钥本身**鉴权，不要账号密码 ——
它的意义就是让拿到密钥的脚本、CI、第三方自助取用。密钥无效、被撤销，
或者服务没开 `--allow-upload` 时一律不下发。响应带 `Cache-Control: no-store`：
脚本里含密钥，不能被中间层缓存。

### 有效期

创建时可选 1 小时 / 6 小时 / 1 天 / 7 天 / 30 天 / 永不过期。
列表里显示每把密钥的状态、剩余时长、最后使用时间与使用次数，可随时撤销；
支持逐条勾选，或「全选」后**批量撤销**。批量撤销会逐个调用撤销接口，
有失败项时汇总提示，已撤销成功的不会回滚。

### 安全设计

- **明文只显示一次**。服务端只保存 `SHA-256(明文)`，`keys.json` 泄露也无法直接使用。
  界面上只展示可读前缀（`gofs_AbCd1234…`）供人工核对。
- **密钥文件权限 0600**，默认放在用户配置目录（`~/.config/gofs/keys.json`），
  不放在服务目录里——否则它会出现在自己的目录列表中。
- **校验用定长时间比较**，避免通过响应耗时逐字节猜测；查找走 `SHA-256` 摘要索引，
  校验耗时是 O(1)，不再随密钥数量线性增长。
- **配额与字段上限**：全局最多 10000 把、单账号最多 1000 把；名称 200 字符、
  备注 2000 字符、scope 1024 字符。启动时清理已过期密钥，避免 `keys.json` 无限增长。
- **删号 / 改密即收回凭据**：账号被删除或重置密码时，它此前签发的上传密钥与
  分享链接一并撤销 —— 断开会话不等于收回已经发出去的 bearer 凭据。
- **改权限也会收回已失效的凭据**：只改规则（不改密码）时，只撤销 scope 根
  已不再满足所需权限的密钥/分享，不会因为一条无关规则把整个 CI 的 key 全部作废。
- **非管理员看不到主机布局**：`keys.json` 的路径只返回给管理员。
- **创建者的权限是上限**：签发时检查调用者对该目录是否有写权限，只对 `/docs`
  有权限的账号签不出覆盖 `/` 的密钥；**每次使用**时还会按创建者当前 ACL
  逐路径复核 —— 更细的子路径收窄（例如后加的 `/docs/finance:r`）会立即生效，
  而不是只靠签发时的一次判断。没有创建者记录的历史凭据在启用鉴权后会被拒绝，
  启动日志会给出提示。
- **scope 拒绝控制字符**：scope 会进入生成的 `/up` 脚本；换行等字符在创建
  时就被拒绝，渲染侧也会把旧数据中的控制字符转成空格，避免注入脚本注释。
- **只能管理自己的密钥**：非管理员在列表里只看到自己创建的密钥，
  也只能撤销自己的；否则任何有写权限的账号都能吊销别人（乃至管理员）的
  上传密钥与分享链接。
- **作用范围在归一化路径上比对**，`//uploads`、`/uploads/../etc` 这类写法绕不过去。
  Unix 上 `\` 是合法的文件名字符，不会在鉴权层被当成路径分隔符
  （Windows 上落盘解析会把它当分隔符，那时只会更严格）。
- **管理接口同样限速**：`/fs/keys` 能验口令，因此与其它认证入口共用
  按「来源 + 账号」隔离的失败计数与封禁（`--auth-fail-limit` / `--auth-fail-window`）。

### 用法

```bash
# 上传（推荐用请求头）
curl -T backup.tar.gz \
  -H 'X-Gofs-Upload-Key: gofs_xxxxxxxx' \
  http://127.0.0.1:5000/incoming/backup.tar.gz

# 或写在查询参数里，便于一行搞定
curl -T backup.tar.gz 'http://127.0.0.1:5000/incoming/backup.tar.gz?key=gofs_xxxxxxxx'
```

失败时：密钥无效或过期返回 `401`，超出允许目录返回 `403`。

### 批量上传（目录连层级一起传）

`-T` 一次只传一个文件。要成批传、还要保留目录结构，用 `-F` 走 multipart 表单 ——
一次请求可以带多个文件，`path` 字段指定它们落到哪个子目录：

```bash
KEY='gofs_xxxxxxxx'
find 目录 -type f | while read -r f; do
  curl -sS -H "X-Gofs-Upload-Key: $KEY" \
    -F "path=${f%/*}" -F "file=@$f" "http://127.0.0.1:5000/"
done
```

用 `find | while read` 而不是 `for f in $(find …)`：后者遇到带空格的文件名会被拆散。

**目录层级为什么要靠 `path` 字段**：multipart 的文件名会被服务端压平到基本名
（`apps/web/index.html` → `index.html`），光靠文件名保不住层级。`path` 是
相对当前 URL 的子目录，`path=apps/web` 就会把文件放进 `apps/web/`。
`path` 里不允许出现 `..`。

**不想按日期自动归档**就再加一个 `-F "dated=0"`。默认行为是：传到服务根目录
的文件会进 `年/月/日/`，传到子目录（含 `path` 指定的）原地放。

写成脚本的话，顺手把「最后一个参数当作目标子目录」也加上：

```bash
#!/bin/bash
# 用法：./gofs-up.sh 文件或目录... [目标子目录]
set -u
KEY='gofs_xxxxxxxx'
BASE='http://127.0.0.1:5000'
DEST=''

args=("$@")
if [ "${#args[@]}" -gt 1 ] && [ ! -e "${args[${#args[@]}-1]}" ]; then
  DEST="${args[${#args[@]}-1]}"
  args=("${args[@]:0:${#args[@]}-1}")
fi

# post <本地文件> <想放到的相对路径>
post() {
  local dir target
  dir=$(dirname "$2"); [ "$dir" = "." ] && dir=""
  target="${DEST:+$DEST/}$dir"; target="${target%/}"
  if curl -sS -f -H "X-Gofs-Upload-Key: $KEY" \
       ${target:+-F "path=$target"} -F "file=@$1" "$BASE/" >/dev/null; then
    echo "  ↑ ${target:+$target/}$(basename "$2")"
  else
    echo "  ✗ $2" >&2
  fi
}

for a in "${args[@]}"; do
  if [ -d "$a" ]; then
    root=$(basename "$a")
    while IFS= read -r f; do post "$f" "$root/${f#"$a"/}"; done < <(find "$a" -type f)
  elif [ -f "$a" ]; then
    post "$a" "$(basename "$a")"
  else
    echo "  跳过（不存在）：$a" >&2
  fi
done
```

```bash
$ ./gofs-up.sh src lone.txt batch
  ↑ batch/src/docs/readme.md
  ↑ batch/src/top.txt
  ↑ batch/src/apps/web/index.html
  ↑ batch/src/apps/web/style.css
  ↑ batch/lone.txt
```

（每组内部的先后取决于 `find` 的遍历顺序，不必一致。）

密钥的作用范围对 `path` 同样生效：一把只允许写 `/docs` 的密钥，
`path=../other` 会被 `400` 挡下，POST 到 `/other/` 则返回 `403`。

## 认证

登录仍用 **HTTP Basic** 校验一次口令，但运行期身份是 HttpOnly 会话 Cookie；页面不依赖浏览器原生登录框。

原生框有几个毛病：无法登出（凭据被浏览器缓存，通常要重启浏览器才失效）、
无法承载「登录后回到原页面」这类逻辑、移动端体验差、样式与应用割裂。
所以这里由应用自己弹登录框。登录成功后服务端下发 **HttpOnly 会话 Cookie**
（`gofs_sid`，HTTPS 根路径下优先 `__Host-gofs_sid`），页面刷新/重新打开时
用它恢复身份；**密码不再写入 `sessionStorage` / `localStorage`，也不在
登录后留在 JS 内存里**。所有后续请求（包括密钥/设置/用户管理）都走会话
Cookie，XSS 读不到 Cookie，也偷不到密码。本地只保留一个用户名标记用于刷新
时先画顶栏。勾选「保持登录」时 Cookie 有效期 30 天，否则是浏览器会话级。
外部 CLI/脚本仍可用 `Authorization: Basic ...`，不要求 Cookie。

### 未登录时的三种行为

| 请求类型 | 行为 | 原因 |
| --- | --- | --- |
| 浏览器导航目录（`Accept: text/html`，无 API 参数） | 返回**应用外壳** `200`，带 `auth_required: true` | 前端才有机会弹自己的登录框 |
| 应用内部请求（带 `X-Gofs-Ajax: 1`） | `401`，**不带**挑战头 | 避免弹出原生框打断应用流程 |
| 直接访问文件（如 `/a.txt`） | `401` + `WWW-Authenticate` 挑战 | 这时原生框反而是最自然的 |

外壳里**不含任何真实数据**：目录列表是空的，权限位全为 false，
上传归档等配置也不下发，未登录者拿不到任何文件名或目录结构。

### 刷新页面为什么不用重新登录

浏览器自己发起的导航会带上 HttpOnly 会话 Cookie，但页面里的 JS 请求不会
自动加 `Authorization` 头。所以按 F5 时，前端会调一次
`GET /fs/auth?path=<当前路径>`（不带 Basic），服务端用会话 Cookie 换回身份、
权限与配置，再用这些重新渲染。如果这一步返回 `401`，说明会话已过期，
前端清掉内存凭据并弹出登录框。

旧版本遗留在 `sessionStorage` / `localStorage` 里的明文密码会在启动时被
主动清除，不再读取。

**登录成功后同样不做页面跳转**，而是前端自己 `fetch` 数据渲染 ——
跳转会陷入「跳转后浏览器不带凭据」的死循环。

### 受限账号在子目录里也能拿到完整按钮

`/fs/auth` 支持 `?path=` 参数，按指定路径计算权限。
一个只被授予 `/docs:rw` 的账号，站在 `/docs` 里应该看到完整的操作按钮，
而不是被当成只读——不传 `path` 时才按根目录计算。
路径里含 `..` 会被直接忽略，不会借机提升权限。

### 命令行

`curl -u user:pass` 照常可用；`--anyauth` 也能走挑战流程。

## 用户与权限

账号有两个来源，页面上分得很清楚：

| 来源 | 怎么改 | 密码存法 |
| --- | --- | --- |
| **启动参数**（`-a` / `GOFS_AUTH`） | 规则只能改命令行后重启；**密码可在顶栏「改密」中修改**，保存为覆盖值 | 未改密时是命令行明文；改密后是 PBKDF2 覆盖值 |
| **用户表**（`users.json`） | 登录后点顶栏**「设置」→「用户与权限」**标签，随时增删改 | **PBKDF2 摘要**，服务端也拿不回明文 |

两边合并后一起参与匹配；**同名时以启动参数为准**（而不是启动失败 ——
用户表文件可能比命令行先存在，谁对谁错很难说，但「命令行是权威」简单且不会卡住服务）。

### 修改自己的密码

任何登录成功的账号（用户表或启动参数）都能自助改密，不需要管理员权限：
点顶栏账号芯片里的**「改密」**（手机端在「更多」菜单里），填写当前密码、
新密码并确认即可。只被授予 `/docs` 只读权限的账号也能改自己的密码 ——
这是账号最基本的自我保护，与路径权限无关。

- **必须提供当前密码**：会话 Cookie 可能被窃取，只凭 Cookie 就能改密等于让
  攻击者一进门就把主人锁在外面。
- **改完即下线**：该账号的所有会话（包括发起本次修改的那一张）都会作废，
  需要用新密码重新登录；它此前签发的上传密钥与分享链接也一并撤销。
- **启动参数账号也能改**：`-a` / `GOFS_AUTH` 里的密码仍以命令行为准，但页面
  改密会作为**覆盖值**写进 `users.json` 的 `startup_passwords` 段，重启后
  仍然有效。覆盖值记录了创建时命令行密码的摘要：之后如果修改了 `-a` 里的
  密码，覆盖值会自动失效并以新命令行密码为准，不会出现「改了命令行却登不上」。
- **没有持久化用户表时只存内存**：`--user-file` 为空时，改密只对本次运行有效，
  重启后回到命令行密码；改密弹窗会明确提示这一点。
- **失败有限速**：当前密码输错按独立的 `password` 类别计入认证失败限速，
  不会连坐同一 IP 的正常登录与匿名访问。

对应接口是 `POST /fs/auth/password`，见下面的 API 示例。

### 权限模型

沿用命令行那套「路径 → 权限」，**按最长前缀匹配，未命中的路径一律拒绝**：

```
alice 的规则： /docs 可读写　/ 只读
  → /docs/a.txt      可读写
  → /docs2/a.txt     只读（前缀按「目录段」匹配，/docs2 不是 /docs 的子路径）
  → /other/a.txt     只读
```

界面上就是一列「路径 + 权限」行，可以加多行。想给某人「只有某个目录能写、
其他位置能看」，就是上面这两行。

因为规则可以细到单个文件（`/docs:rw` + `/docs/secret.txt:r`），
**写操作按目标文件本身复核，而不只看所在目录**：表单上传、批量重命名、
解压（逐个条目）都会在动手前检查最终路径；任一目标没权限就整体拒绝，
不会出现「前几个已改、后面才发现越权」的半完成状态。

**软链按真实目标复核。** 请求路径命中 `/docs:rw`，但 `/docs/link` 指向
`/secret.txt` 时，读写仍按 `/secret.txt` 的规则判定；文本读写、Office 预览、
解压源/目标、上传目标、移动目标、上传密钥的 scope、普通文件读写下载都在
路径权限之外再看一次真实路径。分享令牌与上传密钥没有可表达根外的规则，
不能借软链跳出范围；只有普通账号在显式 `--allow-symlink` 时才允许根外目标。

**递归操作逐项复核。** 只检查目录本身挡不住「目录可写、其中某一项只读」：
递归删除 / 覆盖目标目录会遍历每个后代要求读写权限；移动或重命名目录会
逐个比较后代在新旧 URL 下的权限，**新位置不得高于旧位置** —— 否则可以把
只读子项搬到一个规则更宽的位置再改写。

**ACL 按磁盘真实名字匹配。** macOS / Windows 的文件系统大小写不敏感，
macOS 还会做 Unicode 规范化、Windows 还接受 8.3 短名与尾随空格点；
如果 ACL 按请求里的字面量匹配，一条更具体的只读规则就可能被大小写变体绕到
更宽的读写规则下。所以这两个平台会把已存在的路径段映射成磁盘上的真实名字
再匹配（每个请求内缓存，避免反复 `ReadDir`）；Linux 常规文件系统区分大小写，
不做这段 IO。Linux 的 casefold 目录仍是已知限制。

### 安全设计

- **密码只存摘要**：PBKDF2-HMAC-SHA256，21 万轮 + 每用户独立随机盐，
  32 字节派生密钥。落盘文件权限 `0600`，写盘走「随机临时名 + `fsync` + `rename`」，
  不接受可预测的 `users.json.tmp`（本地攻击者可预置软链，诱导服务覆盖任意文件）。
- **删号 / 改密会撤销该账号签发的密钥与分享**：会话由 auth 层作废，同时按创建者
  撤销上传密钥与分享链接，避免「删了账号，旧凭据仍能访问」。
- **改规则会定向撤销失效凭据**：只撤销 scope 根已不再满足权限的 key/分享；
  使用侧还会按创建者当前 ACL 逐路径复核，子路径降权无需依赖撤销时机。
- **定长时间比较**，避免按耗时逐字节猜摘要。
- **未知用户名也跑一次等成本的 PBKDF2**：否则「用户不存在」会明显比
  「密码错误」快，等于给出一条枚举账号的侧信道。
- **PBKDF2 并发有闸门**：同时最多 `min(CPU, 8)` 次计算，排队超过 2 秒的
  校验直接失败（fail closed），避免大量并发登录把 CPU 打满。
- **验证明文永不出现在响应里**：接口只返回用户名、规则与时间戳。
- **改密码立刻生效**：密码校验有一层结果缓存（见下），任何改动都会整体清空它，
  否则旧密码会因为命中缓存而继续有效。
- **启动参数里的明文账号也跑等成本 PBKDF2**：它们只做定长比较会明显快于用户表
  账号，攻击者可以据此枚举启动账号名；现在补一次等成本的派生计算并共用结果缓存。
- **只有管理员能用**：判定与「服务设置」完全一致（对服务根有读写权限），
  与界面入口的显隐共用同一套条件，避免「按钮在但点了 403」。
  连账号列表都不给非管理员看 —— 账号名本身也是信息。
  未启用鉴权时默认无人是管理员（见「无鉴权部署的管理面」）。
- **启动参数里的账号规则不可删改**：想摘掉就去改命令行。密码例外 ——
  可在页面改密，以覆盖值落盘；改 `-a` 里的密码会让覆盖值自动失效。
- **防呆**：如果一次改动会**带走最后一个对根目录可读写的账号**，会被拒绝，
  并说明原因。否则就再没有入口能管理了。
- **未启用鉴权的部署不允许建用户**：那种情况下加第一个用户的副作用是
  「所有人立刻要登录」——包括正在操作的你。必须先用 `-a` 配一个账号。

### 为什么密码校验要带缓存

HTTP Basic 意味着**每个请求都要验一次密码**，而 PBKDF2 是按「故意很慢」
设计的（21 万轮 ≈ 100ms）。真按这个算，每个请求都要多花 100ms，服务基本不可用。

所以有一层「用户名+密码摘要 → 是否匹配」的内存缓存（上限 512 条，
键是 `SHA-256(用户名 + \0 + 密码)`，所以内存里也不留明文）。
首次校验某个组合时算一次 PBKDF2，之后直接命中。
任何一次用户表改动都会清空整个缓存 —— 这是「改密码立刻生效」的保证。

缓存没命中时，PBKDF2 还要先过并发闸门（最多 `min(CPU, 8)` 个同时算）。
这不影响正常使用 —— 同一账号的后续请求都命中缓存，只有「新组合」才计算；
它挡住的是「用海量不同密码并发探测」把 CPU 占满。

### 启动时的账号口令

- **`cmd/app`** 是给人上手看的示例入口：账号固定为 `admin / admin123`，
  并且只监听 `127.0.0.1`。它还**强制锁定监听地址与端口、只使用内存存储**，
  不会读取或写入真实的 `keys.json` / `users.json` / `settings.json` ——
  否则设置文件里一条旧的 `0.0.0.0` 记录就能把固定口令的示例推到公网。
  不要把它直接对外部署 —— 对外请用 `cmd/gofs` 并显式用 `-a` 配置账号。
- **库里的 `gofs.Run`** 不带默认口令：每次启动随机生成管理员口令并打印
  一次，同样只监听 `127.0.0.1`。

### API

```bash
# 列出账号（管理员）
curl -u admin:secret http://127.0.0.1:5000/fs/users

# 新建：alice 在 /docs 可读写、其他位置只读
curl -u admin:secret -X POST -H 'Content-Type: application/json' \
  -d '{"name":"alice","password":"alice123","rules":[
        {"path":"/docs","perm":"rw"},{"path":"/","perm":"r"}]}' \
  http://127.0.0.1:5000/fs/users

# 改权限（省略 password 就是不改密码）
curl -u admin:secret -X PUT -H 'Content-Type: application/json' \
  -d '{"name":"alice","rules":[{"path":"/docs","perm":"r"}]}' \
  http://127.0.0.1:5000/fs/users

# 删除
curl -u admin:secret -X DELETE \
  'http://127.0.0.1:5000/fs/users?name=alice'

# 账号自助改密（普通账号即可，不需要管理员；成功后该账号所有会话与密钥作废）
curl -u alice:alice123 -X POST -H 'Content-Type: application/json' \
  -d '{"current_password":"alice123","new_password":"new-pass-456"}' \
  http://127.0.0.1:5000/fs/auth/password
```

`perm` 取 `"rw"`（可读写）或 `"r"`（只读）。响应始终是更新后的完整列表，
前端一次往返就能刷新。错误一律是 `400` + 可读的说明
（重名、密码太短、路径含 `..`、同路径重复、来自启动参数、最后一个管理员…），
界面会直接把这段文字显示出来。

### 落盘

用户表默认在 `<用户配置目录>/gofs/users.json`，可用 `--user-file` 改；
置空则只保存在内存中（重启即失效）。

```json
{
  "version": 1,
  "users": [
    {
      "name": "alice",
      "salt": "IBi1OQXu6BcAFSRc51ZrPw==",
      "hash": "qwTkyz7qePzE3slyT/fQT3btH8t+NlNa/XEykY+ogxw=",
      "iter": 210000,
      "rules": [{ "path": "/docs", "perm": "rw" }, { "path": "/", "perm": "r" }],
      "created_at": 1790604599,
      "updated_at": 1790604599
    }
  ],
  "startup_passwords": {
    "admin": {
      "salt": "UgIOrzIBDykl4MZYN+Bu9Q==",
      "hash": "P5QY6RQ26XlxMGEpwqGCwGLYpB/viPfJiKqrAvAcDZk=",
      "iter": 210000,
      "base_salt": "nJf84et3TlH+Cx/Z7dPubw==",
      "base_hash": "5Qo4pwJzgglzFZt4+9EhThfn6r8SYOf3kc8BnCGI9HI=",
      "base_iter": 210000,
      "updated_at": 1792769116
    }
  }
}
```

`startup_passwords` 只会在启动参数账号在页面上改过密码后出现：`salt/hash/iter`
是新密码的 PBKDF2 摘要，`base_*` 是创建覆盖值时命令行密码的摘要。启动时若
`base_*` 与当前 `-a` 密码对不上，说明命令行被改过，覆盖值会被清除。

文件损坏、账号非法（用户名带空格、没有任何路径权限、摘要字段缺失）、
或 `version` 高于本程序支持的版本时，**启动会直接失败并说明原因**，
而不是静默降级 —— 一个悄悄少了管理员的部署比启动不了更糟。

## 服务设置（运行期）

以前「换数据目录」「放宽上传上限」都得改启动参数再重启进程。现在登录后点顶栏的
**「设置」**，这些事都能在页面上直接改，**立刻生效、不用重启**。

⚠️ **未启用鉴权时，管理面默认关闭**（`/fs/settings` 的写操作、`/fs/keys`、
`/fs/users`、`/fs/upgrade`、`/fs/restart`、`/fs/uninstall` 一律 `403`），
页面上也不显示「设置」入口。`GET /fs/settings` 仍可调用，但只返回上传上限等
非敏感字段，不下发服务根、可切换范围与站点列表。要保留旧的「无鉴权 = 管理员」
用法，启动时显式加 `--allow-anonymous-admin`；banner 会打印当前处于哪种状态。

设置是个**标签页**弹窗，密钥、用户与权限、升级与重启都收在里面，按权限显示：

| 标签 | 内容 |
| --- | --- |
| 常规 | 站点标题、访问路径前缀、高级网络设置（监听地址与端口，默认折叠并显示当前端点）、主服务目录、附加站点（增删）、上传上限、编辑上限（后五项见下） |
| 密钥 | 上传密钥与分享链接的管理（需 `--allow-keys` 且在某目录上有写权限；分享链接还要求至少开启上传/编辑/解压之一，或显式 `--allow-share`） |
| 用户与权限 | 增删改账号、按路径分配只读/读写（需 `--allow-user-manage` 且为管理员） |
| 升级、重启与卸载 | 检查并执行升级、重启、卸载服务（三者独立注入，按实际可用的显示，标签名跟着变；需为管理员） |

底部按钮跟着当前标签走：常规是「取消 / 保存」，用户与权限是「关闭 / 新建用户」，
其余是「关闭」。常规页有未保存改动时，切标签或关窗会先确认一次。

入口对**任一子功能可用**的账号可见 —— 所以一个只被授予 `/docs` 写权限的账号
虽然看不到「常规」（那需要服务根的读写权限），仍能管自己的密钥。服务端对每个
接口还会再校验一次（见下方「权限」）。

### 这些文件存在哪

三个 JSON 都在**用户配置目录下的 `gofs/`** 里（可用 `--key-file` /
`--user-file` / `--settings-file` 分别改，置空＝只存内存）：

| 平台 | 目录 |
| --- | --- |
| Linux | `~/.config/gofs/`（或 `$XDG_CONFIG_HOME/gofs/`） |
| macOS | `~/Library/Application Support/gofs/` |
| Windows | `%AppData%\gofs\` |

| 文件 | 内容 | 是否跨重启 |
| --- | --- | --- |
| `keys.json` | 上传密钥（只存摘要） | 是 |
| `users.json` | 用户表（PBKDF2 摘要） | 是 |
| `settings.json` | 站点标题、访问路径前缀、监听地址与端口、运行期新增的站点、上传上限、编辑上限 | 是 |

⚠️ 拿不到用户配置目录时，这三个文件的默认路径会变成空串（**仅内存**），
而不是退回当前工作目录 —— 后者很可能就是被服务的根，等于把密钥表放进自己的
目录列表里。

`settings.json` 里的每一项都是**改过才记**（值与启动参数相同时不写）——
所以点「恢复默认」之后文件里不会留下一条旧记录，运维以后改启动参数
仍然生效。运行期切换的**服务根目录不在其中**：那是「这个部署该服务哪个目录」
的声明，属于启动参数，不该被一次页面操作固化。

⚠️ **文件内容在读回时会重新校验**，而不是原样信任。它可能来自旧版本、
被手工改过，或在修复前被越权接口写入：`path_prefix` 要重新过
`NormalizePathPrefix`，`listen_bind` / `listen_port` 要重新过
`NormalizeListen`，并且 unix socket 路径必须是「不存在」或「已经是 socket」。
非法值直接忽略、回落到启动参数 —— 否则一个坏前缀或被指向普通文件的
监听路径会让服务要么起不来，要么把注入带进页面。

⚠️ **访问路径前缀与监听地址是个例外，它们反过来：启动参数优先于文件。**
其它项都是「文件里的值胜出」，这两项刻意相反 —— 因为它们改错之后的后果最严重：
前缀必须与反向代理（nginx）的 `location` 一致，监听端口往往还牵着 Docker 端口
映射、防火墙、systemd unit、代理的 upstream。改成一个没人放通的地址，页面就会
在新旧地址下都打不开，而页面正是改回它的唯一入口。这时唯一的自救办法就是
「用 `--path-prefix` / `--bind` / `--port` 重启一次」，所以参数必须能压过文件。
设置页据此下发 `path_prefix_locked` / `listen_locked`，界面上会说明
「重启后回到参数值」。

路径前缀会被拼进页面的 `href` / `src`，所以输入侧拒绝空白、控制字符、
`?`、`#`、引号、尖括号、反斜杠以及连续斜杠 `//`（浏览器会把它当成
协议相对地址、指向另一个主机），也不允许 `.` / `..` 段；
输出侧还会再做一次 HTML 转义作为兜底。`&`、中文等正常字符不受影响。

设置页把这类低频长说明折进了「反向代理下怎么填？」的原生 `<details>`：
默认只留一句「留空表示服务在根路径（/）；改错会让新旧地址都打不开」，
需要细节时再展开。别让每个字段都先铺三行灰字，把表单读成说明书。

判定「启动参数给过没有」对前缀是「非空即给过」，对端口不能这么算 ——
`--port 5000` 与「默认就是 5000」看不出区别。所以解析阶段会把「用户到底写没写」
记进 `Config.BindSet` / `PortSet`（命令行、`GOFS_BIND`/`GOFS_PORT` 环境变量、
`WithBind`/`WithPort`/`WithUnixSocket` 都算），运行期设置据此决定重启后听谁的。

⚠️ **改监听地址是「立即重绑」**：新监听先建起来、成功了才关掉旧的（失败时旧地址
一点没动，页面照常服务）。只关监听、**不断连接** —— 正在跑的上传/下载会跑完，
只是**新**连接走新地址。这跟「重启」的语义不一样，界面上的确认框会讲清这一点。
若当前请求不是直达监听端口（前面挡着反向代理），界面**不会**跳转，只提示你去
改代理的 upstream —— 那种部署下改监听端口只改了上游那一侧。
以库方式嵌在别人的 HTTP 服务里（宿主自己监听）时这一栏不显示：重绑该由宿主决定。

⚠️ **unix socket 路径只会清理「残留的 socket」**：路径上是普通文件、目录或软链
时直接拒绝，绝不会为了重新监听而删除它们（否则「改监听」就成了一条任意文件
删除的入口）。仍在被其它进程服务的 socket 也不会被抢走 —— 重绑前会先试连，
连得上就报「正在被其它进程使用」。改监听接口在调用任何自定义 `Relistener`
之前同样先做这项检查。

⚠️ **升级提示**：早期版本少了 `gofs/` 这一层，文件直接躺在用户配置目录里。
现在启动时会**自动把它们搬到新位置**（只动默认路径、不覆盖已有文件、可重复
调用）—— 既有密钥与用户表不会丢。若你显式指定过 `--key-file` 之类，那些
路径不受影响，也不会被搬。banner 里会打印实际生效的路径，照它看就行。

⚠️ **以 systemd 服务运行时**：系统级 unit 默认**不设 `HOME`**，而两个
`os.User*Dir()` 都依赖它。此时 gofs 会退回**账号的真实家目录**（查
`/etc/passwd`，不依赖环境变量），所以仍然落在 `~root/.config/gofs/` 这种
绝对路径上 —— 实测过，不会跑到服务的 `WorkingDirectory` 里去。要更明确的话，
在 unit 里写一行即可：

```ini
[Service]
User=root
Environment=HOME=/root
Environment=XDG_CONFIG_HOME=/root/.config    # 可选，优先级高于 HOME
```

### 站点标题

浏览器标签页与顶栏品牌名用的是同一个值，默认 `gofs`：

```bash
gofs --title "我的网盘" /srv/data        # 启动参数（也可用 GOFS_TITLE）
```

管理员在「设置 → 常规」里能随时改，**会落盘**（默认
`<用户配置目录>/gofs/settings.json`，用 `--settings-file` 改路径、置空则只存内存）。
改完本页立刻生效 —— 标签页与顶栏当场变；**其它已打开的页面要刷新**才看得到。

> 启动参数给的是**初始默认值**：一旦在页面上改过，之后就以设置文件为准 ——
> 实测重启后仍是页面里设的那个值，而不是 `--title`。上传上限 / 编辑上限同理。
> 想回到启动参数的值得用界面上的「恢复默认」，或删掉那个文件。
>
> 运行期切换的**服务根目录不落盘** —— 那是「这个部署该服务哪个目录」的声明，
> 重启回到启动参数给的根。

### 多个服务目录（站点）

**主目录永远服务在 `/`**，另外可以挂若干个**站点**在 `/<标签>/` 下：

```bash
gofs -A ./data ./backup /srv/projects
#   /            → ./data      （第一个位置参数是主目录）
#   /backup/…    → ./backup
#   /projects/…  → /srv/projects
```

也可以用 `gofs.WithRoots("./data", "./backup")`（库方式）。

**站点可以在页面上运行期增删**：「设置 → 常规 → 附加站点」里填目录路径点
「新增站点」，立刻挂在 `/<标签>/` 下；每行右侧有「移除」。它们**即时生效**
（不必点「保存」）并写进设置文件，**重启后还在**。

新建的站点会**出现在根目录的列表里**（带一个「站点」标记），点进去就是它；
子目录里不会重复列 —— 站点只挂在根这一层。条目上的「移动 / 重命名 / 删除」
是**不显示**的：它代表的是另一个挂载根，那几个动作对它没有意义（服务端按
解析后的绝对路径判定，真发过去也是 403）。

```
附加站点
  /backup/   /srv/backup           [移除]
  [要新增的目录绝对路径...] [标签（可留空）] [新增站点]
```

安全边界：**默认只允许启动根的同级目录** —— 与「运行期换根」同一套范围。
新增站点会把服务根之外的目录暴露给对 `/` 有读写权限的账号，因此不再默认
放开主机任意目录。确实需要挂载任意位置时显式打开：

```bash
gofs -A --allow-any-site /srv/data          # 允许管理员挂载主机任意目录
gofs -A --root-allow /srv --root-allow /mnt /srv/data
#       ↑ 只允许这些前缀下的目录成为站点
```

`--root-allow` 同时约束换根与加站点；`--allow-any-site` 只放开加站点。
单文件模式下两者都不允许使用（单文件模式的边界不能被页面展开）。

升级兼容：设置文件里**已经存在**的站外站点会按历史配置继续恢复，并打印一条
安全提示；通过接口**新增**站点仍按新默认收紧。确认不需要时移除该站点，或
补上 `--root-allow` / `--allow-any-site`。

`--no-root-switch` 会连同站点增删一起关掉。

几条规则：

- **单个目录时行为完全不变**：仍然服务在 `/`，URL 里没有前缀，运行期换根照旧可用。
- **主目录地址永不改变**：增删站点只影响新站点自己 —— 这正是把主目录钉在 `/`
  的理由（否则加上第二个站点，所有书签与正在浏览的页面都会失效）。
- **重名自动加后缀**（`backup`、`backup-2`），按加入顺序先到先得，结果稳定 ——
  否则重启一次用户收藏的地址就换了。
- **被移除的标签进程内不再复用**：删掉 `backup` 再挂一个别的目录，拿到的是
  `backup-2`。代价是多一个后缀，换来的是**旧书签永远不会被悄悄指到另一个目录**。
- **`fs` 与 `s` 是保留标签**：`/fs/*` 是内部接口、`/s/*` 是分享地址，
  所以目录真叫 `fs` 时会拿到 `fs-2`。
- **互相嵌套的目录会被拒绝**（`/a` 与 `/a/b` 同时给）：路由按 URL 首段，
  而反向映射按路径包含关系，嵌套时同一个文件会有两个地址。启动与新增时都会
  报错并指出是哪两个路径，好过让人自己猜。

⚠️ **`/标签` 会遮蔽主目录下的同名子目录**：主目录里有个 `backup/`，同时又挂了
标签为 `backup` 的站点时，`/backup/x` 走**站点**。这是所选 URL 形状的固有代价。
新增站点时，如果现有 ACL 规则落在该标签下（例如原本针对主目录 `/backup` 的
`-a bob:…@/backup:rw`），服务端会记一条安全提示日志 —— 这些规则会同时作用于新站点，
如非本意请换一个标签或调整规则。

⚠️ **没有「未知前缀 → 404」这回事了**：`/nope/x` 就是主目录下的 `nope/x` ——
`GET` 不存在才 404，而 **`PUT` 会把它创建出来**（和普通上传一样）。

⚠️ **能列出根目录的账号就能看到站点名**。权限规则是最长前缀匹配、没有 deny，
而站点路径都在 `/` 之下 —— 所以「读得到主目录、却看不到某个站点」这个组合
造不出来。站点名本身不是秘密（它只是个路径），但如果你的部署里连目录名都不
该让人看见，就别把那个目录挂成站点。

⚠️ **有附加站点时不能切换主目录**（设置里那一栏变只读）。想换就先移除站点。

⚠️ **权限规则 / 上传密钥 / 分享链接的路径范围要带上标签**：
`-a admin:123@/backup:rw` 才管得到那个站点；一条绑在 `/` 上的旧上传密钥
**不会**覆盖 `/backup/…`。从单根迁到多站点时要一并检查这些范围。

### 可切换的范围

根目录不是想切到哪就切到哪。默认**只能切到启动根目录的同一层**：

```bash
gofs -A /srv/data                 # 默认可切范围 = /srv/*（启动根的父目录）
gofs -A --root-allow /home/me -A /srv/data   # 额外放开 /home/me/*
gofs --no-root-switch -A /srv/data           # 完全禁止运行期切换
```

越界的路径一律 `400`，不会「先把根换掉再报错」。这几类写法会被直接拒绝：

- 目标不存在、不是目录、或为空
- 含 `..` 的路径（`/srv/data/../data` 也会被拒，不做静默归一化后再放行）
- 解析后落在允许前缀之外
- 符号链接指向允许范围之外

### 权限

`PUT /fs/settings` 要求请求者在**服务根 `/`** 上具有读写权限：

- 没有任何凭据 → `401`
- 有凭据但没有根目录读写权限 → `403`
- 上传密钥不能用来改设置（密钥只有上传能力）
- 服务未启用鉴权 → 默认 `403`（管理面关闭），除非启动时加了
  `--allow-anonymous-admin`
- 非管理员读取设置时拿不到根目录、监听地址与端口 —— unix socket 的绝对路径
  同属主机布局信息，也和密钥文件路径一样只对管理员可见

### API

```bash
# 读取当前设置
curl -u admin:secret http://127.0.0.1:5000/fs/settings

# 切换根目录
curl -u admin:secret -X PUT -H 'Content-Type: application/json' \
     -d '{"root":"/srv/other"}' http://127.0.0.1:5000/fs/settings

# 上传上限改成 2 GiB（0 表示不限制）
curl -u admin:secret -X PUT -H 'Content-Type: application/json' \
     -d '{"upload_max_size":2147483648}' http://127.0.0.1:5000/fs/settings
```

响应体：

```json
{
  "root": "/private/tmp/gofs-test",
  "root_switchable": true,
  "allow_roots": ["/private/tmp"],
  "sites_editable": true,
  "upload_max_size": 10737418240,
  "upload_max_size_default": 10737418240,
  "upload_max_size_unlimited": false,
  "upload_date_dir": "2026/09/28"
}
```

`upload_date_dir` 就是拖拽上传会落到的日期目录（见下一节），前端直接拿它做提示。
`upload_max_size` 为 `0`（等价于 `upload_max_size_unlimited: true`）表示不限制。
写操作同样走**跨站来源校验**，`Origin: null` 会被 `403` 拒掉。

## 上传按年月日归档

**默认开启，但只对「直接传到服务根目录」的上传生效**：文件不会堆在根目录下，
而是自动放进 `年/月/日` 三级目录。

```
拖拽 photo.jpg 到根目录        →  /2026/09/28/photo.jpg      ← 归档
拖拽 run.log  到 /projects/logs →  /projects/logs/run.log    ← 子目录，原地放
```

**为什么只归档根目录**：根目录是「一堆散文件」的场景，按日期分三级最有用；
而子目录本身通常已经是有意义的分层（项目名、月份、业务线、某个相机的上传目录…），
再往里套一层年/月/日 只会让目录越陷越深，找文件时反而要点更多层。

设计上的几点考虑：

- **判据是「目标文件的父目录就是服务根」**，与服务端的实际写法一一对应
  （`path.Dir("/a.txt") == "/"` 归档；`path.Dir("/sub/a.txt") == "/sub"` 不归档）。
  前端提示（桌面端投放区 / 上传按钮提示 / 页脚）用的是同一套判断 ——
  **提示与实际落盘不一致，比不提示更糟**。
- **连续拖拽不会越陷越深**。上传完成后页面停留在原目录（不会跳进日期目录），
  否则第二次拖拽就会生成 `2026/09/28/2026/09/28/`。
- **上传前会明确告知落点**。桌面端投放区、拖拽浮层、上传弹窗都写出实际目录，
  只有真的会归档时才追加「（按日期自动归档）」；上传完成的提示带一个「查看」按钮。
- **权限按真实落点复核**。归档改写之后会再判定一次 ACL；软链或大小写别名把目标
  带到另一条路径时，上传密钥的 scope 同样按真实路径复核 —— 根内一条
  `2026 -> private` 的软链不能把写入导进没有写权限的目录。

### 自定义布局

`--upload-date-layout` 接受任意 Go 时间布局字面量：

```bash
gofs --upload-date-layout "2006/01/02" ./data   # 年/月/日（默认）
gofs --upload-date-layout "2006-01-02" ./data   # 2026-09-28
gofs --upload-date-layout "2006/01" ./data      # 只到月份
gofs --upload-date-layout "2006/01/02/15" ./data # 再加小时
gofs --no-upload-dated ./data                   # 关闭，文件一律落在目标目录
```

布局会在启动时用参照时刻试格式化做校验，含 `..`、绝对路径、反斜杠或冒号的写法会被直接拒绝。

### 单次覆盖

需要时可以在一次请求里覆盖默认行为：

| 参数 | 效果 |
| --- | --- |
| `?dated=0`（`false` / `no` / `off`） | 跳过归档，文件落在指定路径 |
| `?dated=1`（`true` / `yes` / `on`） | **强制归档**，即使在子目录里也按日期建目录 |

```bash
# 脚本要精确指定落点
curl -T local.txt 'http://127.0.0.1:5000/direct.txt?dated=0'

# 某个子目录（比如相机上传目录）仍想按日期分层
curl -T photo.jpg 'http://127.0.0.1:5000/inbox/photo.jpg?dated=1'
```

表单上传用同名字段：`dated=0` / `dated=1`。

### 响应头

`PUT` 成功后会返回文件真实落盘的路径，方便脚本确认位置：

```
HTTP/1.1 201 Created
X-Gofs-Path: /projects/logs/2026/09/28/run.log
X-Gofs-Offset: 2048
```

`X-Gofs-Path` 是百分号编码的（HTTP 头只能承载 ASCII），中文文件名不会变成乱码：

```
X-Gofs-Path: /2026/09/28/%E6%8A%A5%E5%91%8A.pdf
```

## 上传文件夹

**整个目录连同层级一起传上去**，不用先在服务端手动建目录。两个入口：

| 入口 | 说明 |
| --- | --- |
| 顶栏上传按钮右侧的 caret →「上传文件夹」 | 打开系统的目录选择框（`<input webkitdirectory>`），选中一个目录即可 |
| 直接把文件夹拖进页面 | 拖拽比选择框更顺手，且**可以一次拖多个目录** |

两个入口最终都收敛成「一组带相对路径的文件」，后面的上传逻辑完全共用。

```
拖 proj/ 到根目录  →  /proj/readme.md
                      /proj/src/main.go
                      /proj/src/util/helper.go
```

（上面是站在根目录的情况；归档规则见上一节 —— 站在子目录里拖文件夹就是原地放。）

实现上有几个不得不注意的点：

- **拖拽目录只有一条路能拿到结构**：`DataTransferItem.webkitGetAsEntry()`。
  `dataTransfer.files` 里根本没有目录内容，所以拖文件夹时只能走 entry 递归。
  另外 `DataTransferItemList` **只在事件派发期间有效**，任何 `await` 之后都会失效 ——
  必须先同步取出 items 并调用 `webkitGetAsEntry()`，再去异步遍历。
- **`readEntries` 要循环调用到空**。规范允许一次只返回一批（Chromium 是 100 条），
  只调一次的话大目录会静默漏文件。
- **路径在下发前清洗一遍**：丢掉空段、`.`、`..`，以及含反斜杠或冒号的段。
  正常来源不会命中（浏览器给的相对路径是安全的），但这是从「用户设备上的文件名」
  拼出来的，值得挡一道。
- **`.DS_Store` 之类不会被特殊处理** —— 拖什么传什么，不做魔法过滤。

### 传文件夹时的进度与并发

- 进度弹窗标题变成「上传文件夹」，正文显示 **`3/57　proj/src/main.go`** ——
  只看百分比的话，一个大目录根本不知道进行到哪了。
- **并发 3 个请求**。传文件夹时绝大多数是几 KB 的小文件，串行的话每个都要等一个
  RTT，几百个文件会慢得离谱；3 是折中值（远低于服务端的并发闸门，速度读数也还稳）。
- **超过 200 个文件先确认一次**，免得手滑把整个 home 目录拖进来。
- **点右上角 ✕ 可以中途取消**：正在排队的文件不再开始，已传的保留，
  提示里如实写出「已上传 X/Y，余下 N 个未上传」。
- **失败汇总成一条**，列出前几个具体原因。传文件夹时失败很容易成片出现，
  逐个弹提示会把界面刷爆。

### 已知限制

**空目录不会被创建**（`a/b/` 里一个文件都没有时，`a/b/` 不会出现在服务端）。
目录选择框和拖拽 API 都不会把空目录作为条目交出来，要支持就得额外发一次 `MKCOL`。
只包含子目录的中间层不受影响 —— 它们会因为下级文件的路径而被自动创建。

## 打包下载

顶栏的「打包下载」按钮有两种行为，取决于当前有没有勾选条目：

| 当前状态 | 按钮文案 | 打包内容 | 下载文件名 |
| --- | --- | --- | --- |
| 未勾选任何条目 | 打包下载 | 当前目录的全部内容 | `<目录名>.zip` |
| 勾选了 N 项 | 打包所选 (N) | 只有勾选的条目 | 单项 `<名字>.zip`，多项 `<目录名>-selected.zip` |

勾选目录时会**递归**打包其内容（包内保留目录本身作为条目，解压后结构不变）。
因此「不勾选直接打包」与「全选后打包」得到的结果是一致的 —— 测试里专门做了这项对照。

搜索结果与空目录下这颗按钮会隐藏：搜索态实际打包的是当前目录而不是搜索结果
（留着容易被误解），空目录只会产出一个空 zip。

### HTTP API

```bash
# 打包整个目录（默认）
curl -OJ 'http://localhost:5000/docs?zip'

# 只打包选中的条目：GET 用重复的 pick= 参数
curl -OJ 'http://localhost:5000/docs?zip&pick=/docs/readme.md&pick=/docs/guide.txt'

# 选中很多时用 POST，避免 URL 超长（浏览器侧走的就是这条）
curl -OJ -X POST 'http://localhost:5000/docs?zip' \
  -H 'Content-Type: application/json' \
  -d '{"picks":["/docs/readme.md","/docs/sub"]}'
```

`pick` 以 `/` 开头时按「相对服务根」解析，否则按「相对当前目录」解析。
不支持逗号分隔 —— 文件名本身可以含逗号，切分会造成歧义。

响应头：

```
X-Gofs-Archive-Mode: all | picked      # 打包的是全部还是所选
X-Gofs-Archive-Entries: 11             # 包内条目数
X-Gofs-Archive-Bytes: 2099             # 原始字节数
X-Gofs-Archive-Skipped: 2              # 被跳过的选中项数（仅 picked 模式）
```

### 安全设计

每个选中项都要过三关，任一不过就被跳过（通过 `X-Gofs-Archive-Skipped` 告知，
前端会提示「有 N 项被跳过（不存在或没有读取权限）」）：

1. **不含 `..`** —— 显式拒绝。`path.Clean` 会把 `../../a` 静默改写成 `a`，
   虽未真正逃逸，但掩盖了调用方的意图（与解压侧的处理保持一致）
2. **能解析到服务根之内** —— 由路径解析器拦掉越界与符号链接逃逸
3. **逐项复核读权限** —— 路径级 ACL 同样生效，不能借打包把没权限的内容带出去

全部选中项都不可用时返回 **400**（而不是给一个空 zip），便于排查路径写错。

刻意**不**要求选中项必须位于当前目录之下：站内搜索是跨目录的，
强制落在当前目录会把「搜索后打包所选」这个用法直接堵死。权限由逐项复核保证，
包内路径优先取「相对当前目录」，不在其下的（搜索命中）退回「相对服务根」，
避免同名文件互相覆盖。

软链接一律不打包（可能指向服务根之外）。

**隐藏规则与目录列举 / 搜索一致**：命中 `--hidden` 的文件不会被打进 zip，
否则就成了「列表里看不见、`?zip` 却能整个导出」。**条目名按 Windows 安全字符清洗**：
服务端文件名里的 `\`、`:` 与 `..` 段会被改写，防止在客户端解压时变成目录穿越或盘符。
客户端断开后目录扫描与压缩会尽快停止。**读不到的文件不泄露主机信息**：包内只写
「权限不足或已删除」的通用说明，带绝对路径的详细错误只进服务端日志。

打包会扫描整棵目录树并持续压缩：它和上传 / 解压 / Office 预览 / `?hash`
共用 `--max-concurrent-jobs` 名额，取不到时返回 503，避免并发打包把
磁盘 IO 与内存拖垮。

## 压缩包在线解压

### 网页上用

1. 目录列表里带「可解压」标记的文件，右侧会多出 **解压** 和 **内容** 两个按钮；
   有解压权限时，直接点文件名后的「可解压」标记也会打开内容清单
2. **内容** → 弹出压缩包清单，可逐个「取出」单个文件（不落盘，流式读取）
3. **解压** → 填写目标目录，确认后弹出实时进度条

### HTTP API

**列出压缩包内容**

```bash
curl 'http://127.0.0.1:5000/fs/extract?path=/backup.zip'
```

响应：

```json
{
  "path": "/backup.zip",
  "format": "zip",
  "default_dest": "/backup",
  "total": 3,
  "truncated": false,
  "entries": [
    {"name": "a.txt", "size": 12, "compressed_size": 14, "is_dir": false, "modtime": "2026-09-28T11:00:00+08:00"}
  ]
}
```

清单与单条目预览同样受 `--extract-max-files` / `--extract-max-total` 约束：
条目超过上限时只返回前 `--extract-max-files` 条并置 `truncated: true`；
预览一个超限条目返回 `413`，而不是把内容读进内存或临时目录。
单条目预览另有 **64 MiB** 的固定上限（更大的条目请直接下载或解压）——
否则少量并发预览就能把临时目录写满。清单/预览与解压共用重任务名额。

**取出包内单个文件（流式，不解压落盘）**

```bash
curl -O 'http://127.0.0.1:5000/fs/extract?path=/backup.zip&file=a.txt'
```

**执行解压（SSE 进度流）**

```bash
curl -N -X PUT http://127.0.0.1:5000/fs/extract \
  -H 'Content-Type: application/json' \
  -d '{"path":"/backup.zip","dest":"/restored","overwrite":false}'
```

返回 `text/event-stream`，逐条推送：

```
event: start
data: {"src":"/backup.zip","dest":"/restored","format":"zip","total":1203}

event: progress
data: {"current":"logs/2026-09/app.log","files":512,"dirs":8,"skipped":0,"bytes":8388608,"total":1203}

event: done
data: {"report":{"files":1203,"dirs":64,"bytes":104857600,"skipped":2,"warnings":["已跳过链接条目 ..."],"elapsed_ms":1840},"url":"/restored/"}
```

出错时推 `event: error`，并在 `data.partial` 里带上已完成的部分统计。

也支持用查询参数调用，方便一行 curl：

```bash
curl -N -X PUT 'http://127.0.0.1:5000/fs/extract?path=/backup.zip&dest=/restored&overwrite'
```

### 安全设计

在线解压面对的是不受信任的输入，因此做了这几层防护：

| 风险 | 处理方式 |
| --- | --- |
| **Zip Slip**（`../../x` 写到目标目录外） | 每个条目路径先统一分隔符、拒绝绝对路径与盘符，再 `SafeJoin` 校验必须落在目标目录内；越界条目跳过并记入 `warnings` |
| **软链接逃逸**（tar 里的 symlink 指向 `/etc/passwd`） | `TypeSymlink` / `TypeLink` 条目一律跳过，不落盘 |
| **目标路径上的软链**（目标目录里预置一条指向根外的软链） | 每个条目（含目录）写出前用 `EnsureWithin` 从卷根逐段解析，悬空软链、软链环一律跳过；`--allow-symlink` 才显式放开 |
| **越过文件级 ACL** | 解压前逐个条目复核最终路径的写权限 —— 「目录可写、单文件只读」的规则同样生效，不通过就整次拒绝；真正落盘前还会对每个写出的目录/文件再复核一次，创建缺失的祖先目录前也逐级复核父目录（只对叶子文件可写，不代表能顺带建出中间目录）。清单被 `--extract-max-files` 截断时直接拒绝解压，不会「检查前 N 条、后面照写」 |
| **解压炸弹**（高压缩比 + 小体积） | 三重限制：条目数上限、写出总字节上限、单文件压缩比上限；zip 的压缩比按中央目录里的**数据偏移算出的物理跨度**计，不再相信可伪造的 `CompressedSize64`；实时累计，超限立即中止 |
| **tar 扫描炸弹**（列清单 / 预览也要顺序解压） | `List` / `OpenEntry` 的**解压扫描量**单独限额：默认不超过 1 GiB（并受 `--extract-max-total` 进一步收紧），超限返回 413。tar 是流式的，定位后面的条目必须先把前面的数据整段跳过 —— 只限制「写出字节数」挡不住不写文件的高压缩比 tar.gz |
| **恶意 zip 中央目录**（声明上百万条目 / 超大目录） | 打开 zip 前先做有界 EOCD 预检：超过 20 万条或 64 MiB 直接拒绝，Zip64 不支持；EOCD 必须紧贴中央目录（带前置数据 / 重定位基址的包装不进），条目数 × 46 字节也不能超过声明的目录大小；`zip.NewReader` 之后再兜一道 20 万条硬上限 |
| **tar 压缩比**（声明值 vs 实际） | 压缩比按归档文件本身的物理大小计算（此前 TAR 硬编码为 0，等于没有压缩比防护）；高压缩比 tar.gz 仍会被写出量与压缩比上限拦下 |
| **超长条目名**（PAX/GNU 单字段可达 1 MiB） | 列表时单字段截断到 4 KiB、整次列表名字预算 16 MiB；解压时名字超过 4 KiB 的条目直接跳过并记入 `warnings` |
| **Windows 特殊路径段**（`C:`、尾随空格 / 点、`.. `、`CON` / `NUL` 等设备名） | 在 Windows 上落盘前直接拒绝；这些写法在 Linux / macOS 上合法，但 Win32 会改写语义，可能越出目标目录或写入 NTFS 备用数据流 |
| **重任务拖垮服务** | 打开压缩包（解析中央目录）之前就要取到 `--max-concurrent-jobs` 名额；清单预览、解压、打包共用同一个池 |
| **权限位提权**（包内 4755 的 setuid 文件） | 忽略包内 mode，文件恒为 `0644`、目录恒为 `0755` |
| **路径歧义** | `dest` / `path` 中出现 `..` 段直接 400 拒绝，而不是静默规范化 |
| **覆盖已有数据** | 目标目录已存在且非空时必须显式 `overwrite=true`；非覆盖模式跳过同名文件 |
| **磁盘打满** | 写出过程用 `io.Writer` 包装器实时拦截，超限即熔断，不会先写满再检查 |

上限可通过 `--extract-max-total` / `--extract-max-files` / `--extract-max-ratio` 调整。
列表与单条目预览的解压扫描量另有 1 GiB 上限（不会为了看一眼清单就把整份
`--extract-max-total` 扫完），超出同样返回 413。

### 关于加密 zip

暂不支持。遇到 `zip` 的加密标记（general purpose bit 0）会直接返回明确错误，
而不是解出一堆损坏文件。如需支持可引入 ZipCrypto 解密。

### 关于中文文件名

`zip` 规范里文件名编码有歧义：Windows 上用 GBK 打包的 zip，Go 标准库不会自动转码。
本项目不引入第三方编码库以保持零依赖，因此这类 zip 的文件名可能显示为乱码
（`tar` / `tar.gz` 不受影响）。如需处理，可引入 `golang.org/x/text/encoding/simplifiedchinese`。

## 安全与防护

文件服务器最容易被击穿的三处是**磁盘、内存与文件描述符**。
下面这些默认值的目标是：被恶意使用时服务退化（返回 413 / 429 / 503），
而不是崩溃或把机器拖垮。全部可调，`0` 通常表示不限制。

### 大文件：能传多大，怎么保证传得完

**流式，不占内存。** 上传与下载都走固定缓冲的 `io.Copy`
（下载用 `http.ServeContent`），内存占用与文件大小无关。
实测 1 GiB 上传/下载各耗时 1 秒上下，进程内存无明显增长。

**超时按「有没有进展」算，不按总时长。** 这是支持大文件的关键取舍：

| 做法 | 后果 |
| --- | --- |
| 固定总时长（如「30 分钟必须传完」） | 10 GB 在 1 MB/s 的链路要 3 小时，会被硬生生掐断 |
| **无进展超时**（默认 2 分钟） | 只要还在传就一直续期，慢速大文件也能传完；只有真正停滞（连上不发/不读）才断开 |

实测：客户端每 0.5 秒读一块、总耗时 8 秒（阈值 2 秒）的慢速下载**完整传完**；
而连上后完全停止读取的连接会在阈值后被断开（读到残留数据后 EOF）。
上传同理 —— 停滞的连接会被及时释放，不占着并发名额。

**断点续传。** 上传中断后不必从头再来：

```bash
# 1) 首传（覆盖写）。中断后服务端留下的是本次内容的前缀
curl -T big.iso http://host/upload/big.iso
# 2) 问服务端已经有多少字节
curl -sI http://host/upload/big.iso | grep -i content-length
# 3) 从断点续传（服务端追加到末尾）
curl -X PUT -H 'X-Update-Range: append' --data-binary @<(tail -c +$((OFFSET+1)) big.iso) \
     http://host/upload/big.iso
```

安全性来自「首传是覆盖写」（`O_TRUNC`）：失败后残留的那部分**一定是本次的内容**，
接着往后写不会把别的文件拼进来。响应头 `X-Gofs-Offset` 是本次写入的字节数，
可以用它确认最终大小等于源文件大小。

**下载支持 Range**，所以客户端的续传、多线程下载、播放器拖动都是现成的。
前端上传大文件走的是 XHR `PUT`（流式直传），**不经 multipart 临时文件**，
所以不占额外的临时磁盘空间；网页端在中断后会自动按上面的协议续传。

### 上传防护

| 限制 | 默认 | 为什么 |
| --- | --- | --- |
| 单次上传字节数 | 10 GiB | 没有它，一个请求就能把磁盘写满 |
| 表单上传（multipart）总量 | 1 GiB | 超过 32 MiB 的部分会落系统临时目录；更大的文件请用流式 `PUT`，它不产生临时文件 |
| 上传读超时（无进展） | 2 分钟 | 防「每秒发几个字节」的连接长期占名额 |
| 并发上传/解压任务 | 64 | 这两类操作长时间占连接与磁盘 IO |
| 文件名长度 | 255 字节 | 超长名交给文件系统会变成 500，提前拒绝更好 |

带 `Content-Length` 的超限请求会在**读任何数据之前**就被拒绝 —— 否则客户端
此时还在往外发数据，它收到的往往是连接重置，而不是那条 413 说明。
超限后若已写了半截文件会被清理掉（追加模式除外，那是续传的续接点）。

**表单上传先校验、后建目录。** 目标目录（含 `path=` 指定的子目录）会先按软链
解析后的真实路径复核写权限，全部文件的目标都验证通过后才 `MkdirAll`；
一个不带文件的 `multipart` 请求会在建目录之前就返回 `400` —— 否则可以借
`path=` 加软链在只读目录下凭空创建目录。

### 攻击面

**跨站写请求（CSRF）。** Basic 凭据由浏览器自动附带，恶意页面只要能让浏览器发一个
请求，就能借用户已登录的会话删文件。所以写方法（POST/PUT/DELETE/MKCOL/MOVE）会校验
`Origin`/`Referer` 与请求 Host 是否同源：

- 浏览器发起的跨站请求**一定**带这两个头之一 → 403；
- curl / 脚本这类非浏览器客户端通常不带 → 不受影响；
- 反向代理改写 Host 而保留 Origin 时可能误判，用 `--no-csrf-protect` 关闭。

**受限账号的路径越权（ACL traversal）。** 鉴权匹配与落盘解析必须使用
**同一条规范路径**。`ServeMux` 只对转义后的路径做规范化，
`/docs/%2e%2e/secret.txt` 不会触发重定向，而 `r.URL.Path` 已经解码成
`/docs/../secret.txt` —— 如果鉴权拿原始值去匹配（命中 `/docs`）、落盘再折叠
`..`（变成 `/secret.txt`），受限账号就能读写自己目录之外的文件。现在的做法：

- HTTP 入口先 `CleanURLPath`，鉴权与解析共用它（保留结尾斜杠语义）；
- `auth.normalizePath` 用 `path.Clean` 折叠 `.`、`..` 与重复斜杠，
  对同一请求必然得到与落盘一致的路径；
- **请求路径不做 trim**：`/docs/uploads `（尾随空格）在 Linux/macOS 上是
  另一个合法文件，若鉴权把它 trim 成 `/docs/uploads`，更具体的读写规则就会
  被套到只应只读的兄弟条目上；规则字面量则在入口处单独 trim；
- 规则本身在归一化**之前**就拒绝原始 `..`，不让歧义输入被静默解释。
- **规范化失败一律 fail-closed（403）**：目录可执行但不可读、fd 耗尽等情况下
  不再回退到请求原路径 —— 在大小写不敏感文件系统上，回退会让 ACL 按错误
  大小写匹配到更宽的规则，而底层打开的却是另一条更严格规则保护的文件。

读取、上传、删除以及跨站点穿越都有回归测试钉着。

**无鉴权部署的管理面。** 「没配账号」不等于「所有访问者都是管理员」。
管理接口能挂载服务根之外的目录、切换服务根、改监听地址、替换二进制甚至卸载
服务 —— 这些已经超出「被服务的那棵目录」。所以未启用鉴权时：

- `PUT /fs/settings`、`/fs/keys`、`/fs/users`、`/fs/upgrade`、`/fs/restart`、
  `/fs/uninstall` 默认一律 `403`，页面也不显示「设置」入口；
- `GET /fs/settings` 仍可读，但不含 `root` / `allow_roots` / 站点列表；
- banner 会打印「管理接口：已关闭」，避免运维点开设置只能靠猜；
- 需要旧的「无鉴权 = 管理员」用法时显式加 `--allow-anonymous-admin`
  （或 `GOFS_ALLOW_ANONYMOUS_ADMIN=true`），风险由部署方承担。

**管理接口的路径输入也是不可信输入。** 两类值尤其危险：

- **访问路径前缀**会被拼进页面的 `href` / `src`。输入侧拒绝空白、控制字符、
  `?`、`#`、引号、尖括号、反斜杠和 `//`（协议相对地址），输出侧再做一次
  HTML 转义；从 `settings.json` 读回时重新校验，旧版本或手工改写的坏值
  不会进入页面。
- **unix socket 监听路径**会交给 `net.Listen`，旧实现会先无条件
  `os.Remove` —— 把路径指到一个普通文件，监听虽然失败，文件已经没了。
  现在只清理「确认是 socket 且没有进程在听」的残留文件；普通文件、目录、
  软链一律拒绝，正在服务的 socket 也不会被抢。持久化的监听设置同样在
  启动时重新校验，非法值直接忽略。

**认证暴力破解。** Basic 认证可以被无限次尝试，按来源统计失败次数，
超过阈值（默认 10 次 / 5 分钟）后临时封禁并返回 429。
只有「带了凭据但不对」才算失败 —— 完全没带凭据只是未登录，
否则一个不带凭据的爬虫就能把正常用户的来源封掉。成功登录会清零计数。

**所有能验口令的接口共用同一套计数**：除了文件接口与 `/fs/auth`，
`/fs/settings`、`/fs/users`、`/fs/keys`、`/fs/upgrade` 也会验证凭据。
漏掉其中任何一个，它就成了不限速的口令猜测入口。应用外壳导航（`Accept:
text/html`）的权限预检同样验口令，因此也走同一套计数。伪造/过期的会话
cookie 同样计入失败；合法但非管理员的会话只回 403，不会把人打进封禁名单。

**来源地址与转发头（`--trusted-proxies`）。** `X-Forwarded-For` / `X-Real-IP` /
`X-Forwarded-Proto` 默认**一概不采信**。否则任何客户端都能随手伪造来源，
绕过认证限速、在日志里冒充别的地址，甚至故意把某个 IP 打进封禁名单。
只有在启动时显式配置了可信代理（IP 或 CIDR）后，且**直连对端**落在列表中，
才会解析转发头：

- `X-Forwarded-For` 从右往左取第一个非可信地址（右侧是代理追加的，
  最左侧可能是客户端自己塞的）；
- `X-Forwarded-Proto` 只认 `http` / `https`，用于判断外部协议 ——
  它同时影响 cookie 的 `Secure`、CSRF 的协议比较与分享链接的生成；
- 同源校验除主机外也比协议：直接跑 HTTPS 时，来自同主机 HTTP 页面的
  写请求会被拒绝；确定不了外部协议时不做协议比较，避免误杀。

```bash
gofs --trusted-proxies 127.0.0.1,::1 -b 127.0.0.1 -p 5000 /data
GOFS_TRUSTED_PROXIES='10.0.0.0/8,192.168.1.10' ./gofs -A /data
```

**慢速攻击。** `ReadHeaderTimeout` 10 秒掐断「连上后慢慢发请求头」（Slowloris）；
请求头总量限制 64 KiB（标准库默认 1 MiB，请求头是每个连接都要缓冲的）。
上传/下载/打包/SSE/大 JSON 响应（目录列举、搜索）/链接索引页都用
「无进展超时」；JSON 等小型 API 请求体则另设 **30 秒绝对时限** ——
几 KB 的请求一个字节一个字节地发，不该长期占着并发名额。
解压接口在读取请求体**之前**就检查功能开关，默认配置下连解析都不会发生。

**资源耗尽。**

| 面 | 限制 | 说明 |
| --- | --- | --- |
| 并发请求 | 512 | 兜住文件描述符与内存，取不到名额时短暂排队后返回 503 |
| 目录列举 | 20000 条 | 十万级文件的目录一次性序列化会吃掉大量内存；响应带 `truncated` 与 `total_all` |
| 打包 | 20 万条 / 50 GiB | 扫描阶段就累计检查，超限返回 413 而不是把内存撑爆 |
| 解压 | 10 GiB / 10 万条 / 200 倍压缩比 | 防解压炸弹；超限时清理残缺文件 |
| 压缩包清单 / 单条目预览 | 10 万条 / 单条目 ≤64 MiB | 列表与预览不是绕过上限的后门：超出截断（`truncated`）或返回 413 |
| zip 中央目录预检 | 20 万条 / 64 MiB（Office 预览 2 万条） | 中央目录体积由压缩包声明；在 `zip.NewReader` 分配内存前先做有界 EOCD 检查，Zip64 直接拒绝 |
| 重任务并发 | 64 | 上传 / 解压 / 打包 / Office 预览 / `?hash` 共用一个名额池（`--max-concurrent-jobs`） |
| `?hash` | 512 MiB | 算摘要要读完整个文件，对超大文件开放等于送出一个 CPU/IO 耗尽入口 |
| 会话表 | 全局 4096 / 单账号 16 | 全局满时拒绝新会话；单账号超出时替换自己最旧的，占不满整张表 |
| 认证失败记录 | 惰性清理 | 避免被大量伪造来源撑爆内存 |

**存储型 XSS。** 文件服务器天然会把上传的 `.html` / `.svg` 原样吐回浏览器，
而浏览器会把它当作**本站页面**渲染 —— 一个能上传文件的人只要放一个
`<script>fetch('/fs/keys',{method:'POST'…})</script>` 再诱导管理员打开，
就能借管理员的登录态为所欲为。所以：

- 所有响应带 `X-Content-Type-Options: nosniff`（禁止按内容猜类型），
  另加 `X-Frame-Options: SAMEORIGIN`（防点击劫持，同时保留 PDF 同源预览）
  与 `Referrer-Policy: no-referrer`；
- HTML / SVG / XML 额外带 `Content-Security-Policy: sandbox`：
  - HTML 用 `sandbox allow-scripts`：静态页脚本可以运行，但文档处于不透明源，
    读不到本站 cookie / localStorage，也发不出带凭据的同源请求；
  - SVG / XML 用 `sandbox`，连脚本也不开放；
  - 需要脚本和同源能力都完整保留时，部署方可显式 `--no-html-sandbox`
    （等于主动承担存储型 XSS 风险）。
- **判据是最终 `Content-Type`，不是扩展名白名单。** `ServeContent` 会把不认识的
  扩展名按内容嗅探，一份 `.md` 或无扩展名文件只要以 `<!DOCTYPE html>` 开头就会被
  当成 `text/html` 执行；`.shtml` / `.xht` 本身就是 HTML 类文档。
  这两类现在都打上沙箱，`frame-ancestors 'none'` 一并封掉嵌入。
- **可写部署里的 `index.html` 同样进沙箱。** 上传 / 编辑 / 解压任一开启时，
  有写权限的账号可以放置或覆盖服务目录里的 `index.html`；而
  `--render-index` / `--render-try-index` / `--render-spa` 会把它当页面返回。
  因此默认加 `sandbox allow-scripts`（脚本可运行，但处于不透明源），
  纯只读部署不加；直接访问 `/index.html` 与 `--render-index` / SPA 两条
  路径口径一致。确认站点文件只由本机运维更新、且确实需要同源应用时，
  才用 `--unsafe-index-html` 显式放开。
- **自定义 `--assets` 默认不能位于服务根内**：`/fs/assets/` 不经鉴权、直接
  `ServeContent`；若该目录同时能被上传写入，任何能上传的人都能放一个同源
  HTML/JS 进去，在管理员浏览器里读取登录凭据。开发时确实需要放在服务目录下，
  才显式使用 `--unsafe-assets-in-root`（启动日志会告警）。
- JSON 响应带 `Cache-Control: no-store`：认证、设置、密钥等响应可能含账号名、
  根目录与一次性明文，不该被浏览器或中间缓存留下副本。
- **受鉴权保护的文件 / 列表响应带 `Cache-Control: private` + `Vary: Cookie,
  Authorization`**：允许用户自己的浏览器缓存（视频拖动、重复下载都依赖它），
  但禁止共享缓存或 CDN 把带凭据的内容复用给其他客户端；匿名公开部署不加限制。

**路径与软链边界。** 路径校验不是「拼字符串后看前缀」，而是从卷根开始逐段
`Lstat`：遇到软链就解析它，最后比较解析结果是否仍在根内。这挡住了两类旧实现
漏掉的逃逸 —— **悬空软链**（叶子指向根外尚不存在的文件，`OpenFile` 会跟过去
创建）与软链环（直接拒绝）。`--allow-symlink` 是部署方显式放开的口子，
默认关闭。

**授权与打开使用同一份快照（TOCTOU）。** ACL 与真实路径复核完成之后，路径仍可能
被换成软链或另一个 inode。现在服务端会记录授权时目标的 inode（新建时记录最近的
已存在祖先），打开时优先用 `os.Root` 从挂载根逐段解析（中途指向根外的软链会被
拒绝），再用 `SameFile` 复核 inode；不一致返回 `409`，不会按旧权限读写另一个
文件。新建文件用 `O_EXCL`，授权后路径若变成软链或已存在文件会直接失败。

这套边界也覆盖**目录操作**：目录列举基于授权时打开的目录 fd，搜索通过
`os.Root.FS()` 遍历；创建目录逐级用 `os.Root.Mkdir`，递归删除、单条删除与
重命名分别走 `os.Root.RemoveAll` / `Remove` / `Rename`（需要 Go 1.25+），
跨设备复制的每个文件也走安全打开。这样即使中途把某一级目录换成指向根外的
软链，也不会在根外建目录、删文件或把整棵树搬走。

**日志注入与凭据脱敏。** URL、User-Agent 以及**文件名**都会进日志。文件名这一点容易被忽略 ——
Linux 上文件名可以含换行，于是 `rm -rf $'a\n127.0.0.1 - - "GET /admin" 200'`
这样一个名字就能在日志里伪造出额外一行。所有日志行在写出前会清理控制字符与 ANSI 转义。
查询串里的 `pass` / `password` / `pwd` / `key` / `token` / `share` / `secret` /
`api_key` 等参数值在落盘前替换成 `***`；判断前会先解码键名，`?pa%73s=` 这类
百分号编码写法同样脱敏。路径形式的分享地址 `/s/<token>/…` 也会把令牌换成 `***`，
否则任何能读日志的人都拿到了 bearer 凭据。自定义日志格式即使显式写了
`$http_authorization` / `$http_cookie` / `$http_x_gofs_upload_key`，值也只会是 `***`。
访问日志**只记录本次请求真正验过密码的账号或有效会话**：`Authorization` 头里
自报的用户名与查询串 `user` 都不作为审计身份（任何匿名请求都能用
`Basic base64("admin:wrong")` 或 `?user=admin` 伪造）。登录后的媒体请求仍会
记录会话身份，不会显示成空用户。日志文件默认权限 `0600`。

**错误信息不外泄。** 未预期的 500 只记服务端日志，响应统一是
`500 Internal Server Error` —— 原始错误里常带绝对路径与系统调用细节，
对攻击者是免费的信息。打包条目、重命名、解压进度里的错误同样只回相对路径或
「权限不足或已删除」这类通用说明，带绝对路径的详情只进服务端日志。

## 反向代理（nginx）

gofs 是个自包含的 HTTP 服务，可以直接听公网端口，也可以躲在 nginx 后面。
完整可拷贝的示例见 [`examples/nginx/gofs.conf`](examples/nginx/gofs.conf)，
下面只说清楚**为什么**要那么写。

### 四条硬性约束

漏掉任何一条都会出问题，而症状往往和原因看起来不相关：

| 约束 | 漏掉的后果 | 原因 |
| --- | --- | --- |
| `proxy_set_header Host $http_host;` | 写操作全部 403、分享链接指向 `127.0.0.1` | 跨站写校验比的是 `Origin` 的 host 与 `r.Host` 是否同源（`internal/server/guard.go`）；分享链接与一键脚本的地址也取自 `r.Host`（`internal/server/up_script.go`） |
| `proxy_buffering off;` | 在线解压进度条全程不动，结束才刷新 | 解压进度走 SSE（`text/event-stream`），nginx 默认会把响应缓冲起来 |
| `client_max_body_size 0;` | 稍大的文件上传返回 413 | nginx 默认 1m，而 gofs 单次上传默认允许 10GiB |
| 启动参数加 `--trusted-proxies 127.0.0.1` | 限速与日志看到的都是代理 IP；分享链接退回 `http://`，Secure cookie 不生效 | gofs **默认不采信任何转发头**。nginx 与 gofs 同机时直连对端就是 `127.0.0.1`（unix socket 同理） |

再配上 `proxy_request_buffering off;`：否则 nginx 会先把整个上传体缓冲到磁盘
再转发给 gofs，几百 MB 以上的上传会先卡一阵，还可能写满临时目录。
gofs 自己会限速、限大小、限并发（见上一节），把缓冲交给它更合适。

gofs 这一侧还要显式声明谁可以给转发头（nginx 与 gofs 同机时是回环地址）：

```bash
gofs -b 127.0.0.1 -p 5000 --trusted-proxies 127.0.0.1,::1 -a 'admin:密码@/:rw' /data
```

没这一行时，上面的 `X-Real-IP` / `X-Forwarded-For` / `X-Forwarded-Proto`
会被**安全地忽略**：服务照常可用，但限速按代理 IP 统计（所有人共用一个桶），
访问日志里也全是 `127.0.0.1`。

### 最小配置

```nginx
server {
    listen      80;
    server_name files.example.com;

    client_max_body_size 0;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;

        proxy_set_header Host              $http_host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering         off;
        proxy_cache             off;
        proxy_request_buffering off;
        proxy_read_timeout      1h;
        proxy_send_timeout      1h;
    }
}
```

`proxy_read_timeout` / `proxy_send_timeout` 要放大：默认 60 秒会掐断长时间
没进展的上传 / 下载 / 解压推送。gofs 侧对这些有自己的「无进展超时」控制
（默认 2 分钟），不需要 nginx 再插一刀。

### 子路径部署

想挂在别的站点的 `/files/` 下时，gofs 加 `--path-prefix /files`，
nginx 侧 `proxy_pass` **结尾不要带斜杠**：

```bash
gofs -b 127.0.0.1 -p 5000 --path-prefix /files /data -a 'admin:密码@/data:rw'
```

```nginx
location /files/ {
    proxy_pass http://127.0.0.1:5000;   # 结尾不带 /：别把前缀剥掉
    # …… 其余同上
}
```

带斜杠会让 nginx 剥掉 `/files` 前缀，而 gofs 的 `--path-prefix` 正需要看到它 ——
剥掉之后页面里生成的链接会少一段，点进去 404。

### unix socket 部署

同机部署时用 socket 更干净，不占端口、也没有「gofs 忘了只监听 127.0.0.1」
的风险：

```bash
gofs -b /run/gofs.sock --trusted-proxies 127.0.0.1 /data -a 'admin:密码@/data:rw'
```

```nginx
upstream gofs_backend {
    server unix:/run/gofs.sock;
    keepalive 32;
}
```

socket 由 gofs 以 `0660` 创建，nginx 运行用户需要有访问权限（同组或改权限）。
unix socket 的对端没有 IP，`--trusted-proxies` 在这里表示「显式信任本地 socket
对端」—— 不配的话，nginx 递进来的转发头同样会被忽略。

崩溃后残留的 socket 文件会在下次启动时被清理并重新绑定；但如果路径上是
普通文件、目录或软链，gofs 会**拒绝启动**而不是删除它。另一个进程仍在
服务的 socket 也不会被抢占（启动时报「正在被其它进程使用」）。

### HTTPS

推荐让 nginx 终止 TLS：在 server 块里加 `listen 443 ssl;` 与证书即可。
**配置了 `--trusted-proxies` 之后**，gofs 会采信 `X-Forwarded-Proto`
（`internal/server/up_script.go`）判断对外协议，所以纯 HTTP 上游也能生成
https 的分享链接与脚本地址，cookie 也会带上 `Secure`；CSRF 同源校验同样按
这个协议比较。没配可信代理时这些头一律被忽略 —— 一键上传脚本会对
HTTP → HTTPS 跳转做同路径重试兜底，但分享链接等仍会生成 `http://`，
所以正确做法还是配上 `--trusted-proxies`。

也可以用 gofs 自带的 `--tls-cert` / `--tls-key` 让上游直接是 https，
nginx 侧 `proxy_pass https://127.0.0.1:5000;`，或改用 `stream` 模块做四层转发。

> 部署在 nginx 之后，额外开关只有 `--path-prefix`（子路径时）与
> `--trusted-proxies`（要真实来源 IP / 外部协议时）。
> 例外是：如果你的代理**必须**改写 Host（比如多域名共享一个后端），
> 那 `Origin` 与 `Host` 就不同源，写操作会被 CSRF 校验挡住 ——
> 这种情况用 `--no-csrf-protect` 关闭校验（只影响浏览器发起的跨站请求，
> curl 等不带 `Origin` 的客户端不受影响）。

## 操作列的按钮

每行只露出**一个主操作 + 一个「更多」**：

- 主操作按文件类型取：目录「打开」、可编辑文本「编辑」、图片 / 视频 / 音频 /
  PDF / Office「预览」、其余「下载」；主操作被禁用（例如超过编辑上限）时自动
  落到下一个可用动作。
- 其余动作（下载、解压、内容、复制链接、分享链接、移动、重命名、删除）
  收进「更多」菜单。

这样一屏不再出现几十个彩色文字按钮，文件名重新成为视觉主角；操作列也从
532px 收到 184px（窄屏 112px），把宽度还给名称列。

「更多」是一个**贴着按钮展开的下拉菜单**（不是弹窗 —— 用户点它是想操作
眼前这一行，弹一个带遮罩的弹窗会打断上下文）。菜单用 `position: fixed`
挂在 `body` 上、按按钮的视口坐标摆位：`.table-wrap` 是 `overflow: hidden`，
挂在表格里的绝对定位菜单会被直接裁掉（越靠下的行越明显）。默认向下、右对齐，
下方放不下就翻到上方，再夹进视口内；点菜单外 / 按 Esc / 页面滚动或窗口变化
都会收起（菜单自身内部滚动除外）。

菜单里始终放**完整动作列表**（包括主操作）。这样即便在极窄宽度下主操作按钮
被兜底逻辑收掉，它仍然能从菜单里点到，不会出现「按钮没了、功能也没了」。`collapseWrappedOps()` 的按实际宽度测量仍保留为极端宽度下的兜底，正常路径不再触发。

## 下载与分享

### 下载走浏览器的原生下载

点「下载」就是**交给浏览器去下**，没有页面里的进度条，也没有额外的中间步骤：

- 浏览器自带的下载管理器负责进度、暂停、**续传**与取消 —— 比页面自己做的完整；
- 不再走 `fetch → blob → <a download>`：那条路要求**整个文件先进内存**，
  几百 MB 的文件足以把标签页拖死；
- 鉴权靠登录时下发的**会话 cookie**：浏览器自己发起的请求会自动带上它。
  这正是当初引入 cookie 的原因 —— 否则裸 `<a href>` 拿不到 `Authorization` 头，
  只会收到 401，也就只能绕道 blob。

打包下载同样是原生的（选中项用 `?pick=` 拼进 URL）。只有一个例外：
**选中项多到 URL 会超长时**（超过 4000 字符，nginx 默认 8KB 会被拒），
才退回 POST + fetch —— 那条路径才有页面内的进度与取消按钮。

### 分享链接（免登录）

行操作里的**「分享」**会生成一条**不需要登录**的地址：

```
https://your-host/docs?share=gofs_XyZ…      分享整个目录（含子目录）
https://your-host/docs/报告.docx?share=…    分享单个文件
```

**文件与目录都能分享**。分享时可以选**访问权限**：

| 权限 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| **只读**（默认） | 读范围内的文件、列目录、预览、下载、打包，在范围内点进子目录 | 上传、删除、改名、解压、编辑 |
| **可读写** | 在上面全部基础上，还能在范围内上传、新建、重命名、移动、删除 | 访问范围之外的路径 |

两种都**看不到范围之外的任何东西**，也都不是管理员 —— 见下面的说明。

几条设计上的取舍：

- **默认只读**：能给出去的最小权限就是默认值。「能删别人文件」必须是一次
  显式选择，而不是勾选框忘改就带出去的默认项。
- **与「链接」是两个按钮，刻意分开**。「链接」复制的地址**仍需登录**，
  适合内部传阅；「分享」才会生成公开地址。「变公开」必须是一次显式动作，
  否则很容易把公开链接当成内部链接发出去。
- **有效期内置，且不提供「永久」**（1 小时 / 1 天 / 7 天 / 30 天，默认 7 天）。
  一条永不过期的公开地址一旦流出就收不回来。
- **随时可撤销**：在「设置」→「密钥」里能看到全部分享链接并撤销
  （列表里会标明每条是「只读」还是「可读写」），和上传密钥用同一套列表。
- **创建它受「只能授出自己有的」约束**：上传密钥要求写权限，只读分享要求
  读权限，**可读写分享要求读写权限** —— 一个只有读权限的账号签不出可读写分享。
  每次访问时还会按创建者**当前** ACL 复核目标路径，后续收窄权限立即生效。
- **只读实例默认不能分享**：没有上传 / 编辑 / 解压的部署，不会仅凭 `--allow-keys`
  就多出一条公开只读通道；确实需要「只读但可分享」时显式加 `--allow-share`。
- **可读写分享不是管理员**。即使把范围设成 `/`，它也只是「能在 `/` 里读写文件」：
  「服务设置」（换根目录、重启、卸载）、用户管理、密钥面板全部拿不到。
  分享令牌只带「范围 + 权限级别」，从头到尾没有身份，因此永远不进入管理员判定。
  有测试专门钉着这条。
- **分享 Cookie 不会把已登录的管理员降级**：权限取「分享令牌」与「真实身份」中
  较高者。管理员打开一次只读分享后，自己的会话仍然是管理员；纯分享访客的
  身份侧只有匿名规则，仍然只拿到分享范围内的权限。
- **两种凭证不能互相冒充**：上传密钥当分享链接用会被拒（那是权限提升），
  反之亦然（只读分享令牌也不能当上传密钥用）—— 都有测试钉着。

### 用 wget / curl 下载分享内容

分享链接有**两种形式**，效果一样：

```
https://your-host/s/<token>/docs/            ← 复制出来的就是这个
https://your-host/docs?share=<token>         ← 等价写法
```

> 前缀 `/s/` 是特意取短的 —— 这条地址是发给别人看的。它从早先的
> `/__share__/` 改过来，**改之前发出去的旧链接会失效**（分享链接本身
> 有有效期，最长 30 天）。⚠️ 服务目录下真有个叫 `s` 的目录时，
> `/s/<token>/…` 会优先按分享地址解析，那个目录的顶层路由会被遮蔽。

**在分享页里翻子目录时，地址栏会保持在路径形式上**（`/s/<token>/docs/sub/`），
不会退化成 `/docs/sub/` —— 后者复制给别人打开只会看到登录框。页面里的接口
调用（列目录、搜索、预览、编辑器、解压）会各自带上令牌：文件空间的地址靠
路径前缀，`/fs/*` 那批接口靠 `?share=`（它们不在分享目录下面，前缀覆盖不到）。

命令行工具用起来是这样：

```bash
# 单个文件
wget -O 报告.docx "https://host/s/<token>/docs/报告.docx"
curl -O "https://host/s/<token>/docs/报告.docx"

# 整个目录（递归）
wget -r -np -nH --cut-dirs=2 -P out "https://host/s/<token>/docs/"
#   out/docs/readme.txt
#   out/docs/子目录/deep.txt
```

**为什么要用路径形式而不是 `?share=`**：wget 会把查询串拼进文件名，
递归下载下来的是 `readme.txt?share=gofs_xxx` 这种没法用的名字；
路径形式下所有链接都是普通相对路径，文件名是干净的。

**为什么命令行能遍历下去**：原来的 HTML 视图返回的是 SPA 外壳，
文件名由前端用 JS 画出来 —— 服务端吐出的 HTML 里**一个 `<a>` 都没有**，
`wget -r` 只能拉到一个空壳。现在对**不声明要 HTML** 的客户端
（`Accept` 里没有 `text/html`，wget / curl 默认发的就是 `*/*`）
返回一份服务端渲染的链接列表。浏览器一定带 `text/html`，拿到的仍是原来的页面。

打开分享链接时，服务端还会下发一个 **Path 限定在分享范围内**的 cookie。
这不是为了记住登录：目录分享打开的是页面，而页面里的列表、预览都是前端
再发 XHR 拉的，那些请求不带 `?share=` —— 没有这个 cookie 就会全部 401。
HTTPS 根路径下，根范围分享使用 `__Host-gofs_share`，子路径分享使用
`__Host-gofs_share_<scope 摘要>`（都是 `Secure` + `Path=/`、不带 `Domain`），
同站子域无法用 Domain Cookie 覆盖或伪造；选择时还会按令牌自身的 scope
匹配当前路径。根路径部署不再采信旧名 `gofs_share`；子路径 / 纯 HTTP 部署
继续使用旧名字。

## 在线检测升级、重启与卸载（扩展点）

页面上有「升级、重启与卸载」这一页（名字跟着实际可用的能力走）：
点「检查更新」→ 有新版就显示版本号、发布说明与发布页 → 确认后「立即升级」
→ 进度实时推送（下载 / 校验 / 替换）→ 重启后生效。

**但 gofs 自己不实现「怎么查、怎么装」，也不实现「怎么重启 / 怎么卸载自己」** ——
它只定义接口，实现由部署方给：

```go
type Upgrader interface {
    Check(ctx context.Context) (*Release, error)
    Upgrade(ctx context.Context, rel *Release, onProgress func(UpgradeProgress)) error
}

type Restarter interface {
    Restart(ctx context.Context) error
}

type Uninstaller interface {
    Uninstall(ctx context.Context) error
}

srv, _ := gofs.New(
    gofs.WithRoot("./data"),
    gofs.WithVersion("1.4.2"),             // 服务对外报告的版本
    gofs.WithUpgrader(myUpgrader{}),       // 不注入＝不提供在线升级
    gofs.WithRestarter(myRestarter{}),     // 不注入＝不显示「重启」按钮
    gofs.WithUninstaller(myUninstaller{}), // 不注入＝不显示「卸载」按钮
)
```

这几个接口**相互独立**（还有 `Relistener`，见「服务设置（运行期）」）：
只升级不重启、只重启不卸载、**只卸载不重启**都很常见。标签页在任一可用时
出现（名字跟着实际能力走，如「升级、重启与卸载」），页内再各显各的块。

⚠️ 「只卸载不重启」是刻意支持的。早先的写法是从 `Restarter` 上做类型断言
（`cfg.Restarter.(Uninstaller)`），那样「想暴露卸载但不想暴露重启」的部署
会被迫连「重启」按钮一起露出来 —— 所以改成了单独的注入点。

重启的常见实现（`RestarterFunc` 可以省掉一个只为实现接口而存在的类型）：

```go
// ① 原地重执行自己（注意：这时 HTTP 响应多半发不出去）
gofs.WithRestarter(gofs.RestarterFunc(func(ctx context.Context) error {
    return syscall.Exec(os.Executable(), os.Args, os.Environ())
}))

// ② 优雅退出，交给 systemd / supervisor / 容器编排拉起
gofs.WithRestarter(gofs.RestarterFunc(func(ctx context.Context) error {
    return syscall.Kill(os.Getpid(), syscall.SIGTERM)
}))
```

⚠️ 前端的等待逻辑据此设计：**「连接被掐断」被当成重启的正常表现**，
不是失败 —— 实现方如果是原地重执行，进程镜像在写出响应之前就被换掉了，
客户端只会看到连接中断。所以页面在发出请求后会轮询 `/fs/health`
（该接口不需要鉴权）等服务回来，最长 60 秒。能拿到完整响应才说明重启
没发生（403/404/500），那时才按失败处理并把服务端的说明原样显示。

重启会清空内存里的会话表，**重启后需要重新登录**（界面上有这句话）。

为什么做成接口而不是内置一种实现：

- **更新源五花八门**（GitHub Releases、自建接口、内网制品库），内置一种必然有人要改；
- **「下载一个二进制并替换自己」是权限极高且不可逆的动作** ——
  校验策略（摘要、签名、来源白名单）该由部署方按自己的威胁模型决定，
  不该由库替他们拍板。

接口与阶段常量（`Release` / `UpgradeProgress` / `Upgrader` /
`StageDownloading` …）都是 root 包导出的。未注入时相关接口返回 404，
页面上**整块都不显示** —— 免得给一个点了必然失败的按钮。

版本号不再写死：`Config.Version` 由上层通过 `gofs.WithVersion()`（或 `GOFS_VERSION`
环境变量、构建期 `-ldflags -X .../config.DefaultVersion`）指定，默认 `0.1.0`。
升级实现判断「有没有新版」时要用同一个值，例如 `githubupgrade.Options.CurrentVersion`。

安全上的几条：

- **只有管理员能用**（对服务根有读写权限）。升级会替换正在运行的二进制，
  这是这台机器上权限最高的操作之一，匿名与只读账号都会拿到 401/403。
- **执行前重新向更新源确认版本**：请求体里的 `Release` 不被信任，服务端会
  再调一次 `Check`；拿不到或版本已变化就分别返回 502 / 409。实现方收到的是
  服务端刚取到的对象，`FullURL` / `PatchURL` 不能被客户端伪造。
- **更新源必须 HTTPS**（本机回环镜像除外）：否则中间人可以同时替换二进制和
  校验和，摘要校验就形同虚设。`githubupgrade` 在构造时直接拒绝非 HTTPS 的
  `APIBase`；页面上的「查看发布页」也只接受 `https://` 链接。
- **默认要求签名校验**：`githubupgrade` 未配置 `PublicKey` / `PublicKeyText`
  时会直接拒绝构造，除非显式设置 `AllowUnsigned`；配置公钥后必须有
  `checksums.txt.sig` 且验证通过，否则升级在落地前中止。
- **同一时刻只允许一次升级**。两个管理员同时点会并发写同一个二进制，
  那是把文件写坏最直接的方式；第二个请求收到 409，正文里带上
  「开始于 15:32:10，已运行 6m3s」—— 光有状态码分不清「别人刚点了一下」
  和「上一次卡住了、锁一直没还」，而这两种情况的处理方式完全不同。
  前端会把这段说明原样显示出来，不要退化成「升级失败：HTTP 409」。
- **重启同样是管理员专属**（`POST /fs/restart`）。它会掐断所有进行中的上传
  与下载，未注入 `Restarter` 时接口返回 404、界面上也不显示那个按钮。
- **卸载（`POST /fs/uninstall`）是独立的扩展点，也是最不可逆的一个**：
  由 `WithUninstaller` 单独注入，与 `Restarter` 无关 —— 没注入就 404、
  按钮也不显示（免得给一个点了必然失败的按钮）。
  **gofs 自己不删任何东西**：删二进制、注销 systemd 单元、清配置目录
  （`keys.json` / `users.json` / `settings.json`）、通知编排器，各部署不同，
  与升级同一个理由 —— 这种事该由部署方按自己的威胁模型决定。
  界面上点「卸载」会先弹一次确认，写明**不可逆**且**不会自动恢复**
  （重启会自己回来，卸载不会 —— 不说清楚用户会像等重启那样干等）。
  它同样有「同一时刻只允许一次」的闸门：卸载**不幂等**，两个管理员同时点
  会在实现方那边交叉着删同一批东西。

  ⚠️ 前端判断卸载成功的方式与重启**相反**：重启是轮询 `/fs/health` 等它
  **回来**，卸载是等它**别回来**。完整拿到一个 4xx/5xx 说明卸载没开始
  （真失败，原样显示）；连接被掐断则视为正常（实现方多半已经把自己删掉并
  退出了）。随后 15 秒的观察窗口里它要是还在应答，页面会如实说「服务仍在
  运行（可能只做了一半）」而不是假报成功。

### 完整示例

`examples/upgrade/` 里有一份**能直接跑**的 GitHub Releases 实现：

```bash
go build -o /tmp/gofs-demo ./examples/upgrade
/tmp/gofs-demo -owner <你> -repo <仓库> -root ./data -port 8080 \
    -public-key <32字节Ed25519公钥（hex或base64）>

# 先只检查、不替换（推荐）
/tmp/gofs-demo ... -dry-run

# 确实无法签名时，显式接受只校验 SHA-256（不推荐）
/tmp/gofs-demo ... -allow-unsigned
```

它把安全上要紧的几步都写全了，可以直接抄：

- **先校验，再替换**。下载完先比 sha256，对不上就在落地前中止，一个文件都不动；
- **校验和取自同一个 release 的 `checksums.txt`**，与二进制同样走 HTTPS ——
  攻击者要同时改两个地方；
- **没有 `checksums.txt` 就拒绝升级**。「校验不了就放行」等于没有校验；
- **默认强制 Ed25519 签名**：给 `githubupgrade.New` 配置 `PublicKey`（或示例的
  `-public-key`），并在 release 里附带 `checksums.txt.sig`，服务端会先验证
  校验和文件的签名再使用它。签名文件内容是 64 字节原始签名或 base64/hex；
  没有签名文件会直接拒绝升级。只有显式设置 `AllowUnsigned`（示例
  `-allow-unsigned`）才会退回只校验 SHA-256；
- **临时文件建在目标二进制的**同目录**下**，这样 `rename` 是原子的；
  放 `/tmp` 再跨设备搬运会在最后一步退化成「复制+删除」，中途崩掉只剩半个文件；
- **替换前先把原文件改成 `.old`**，`rename` 失败还能放回去；
- **按 `GOOS/GOARCH` 挑资产**，拿不到对应平台就报错，而不是随便下一个。

实现本身带测试（`githubupgrade/githubupgrade_test.go`），用假的 GitHub 服务把
「摘要不匹配必须中止」「dry-run 不碰自己」「没有校验和就拒绝」这几条钉住了。

注意**不要用 `go run` 跑它**：`go run` 编译到临时目录，`os.Executable()`
拿到的是那个临时文件，替换它没有意义。

#### 重启示例

`examples/restart/` 是重启那一半的对应示例，两种方式都能直接跑：

```bash
go build -o /tmp/gofs-restart-demo ./examples/restart
/tmp/gofs-restart-demo -root ./data -port 8080

# 默认 -mode exec：原地重新执行自己（不需要 supervisor）
# -mode signal：优雅退出，交给 systemd / supervisor / 容器编排拉起
/tmp/gofs-restart-demo -mode signal ...
```

`exec` 那条实测可用：点一次「重启」，启动横幅会再打印一次（说明进程镜像
真的被换掉重跑了），端口立刻重新绑定，服务目录与启动参数原样保留。两点容易
误判：**TCP 连接会被掐断**（curl 拿到 000）—— 前端把「连接断开」当重启的
正常表现，转而轮询 `/fs/health`；**PID 不变** —— execve 换的是进程镜像不是
进程本身，别拿 pid 判断重启有没有生效。

`-mode signal` 在没有 supervisor 的环境里只会让服务停下来（示例进程没有
托管者），所以默认不开；它演示的是「退出交给外部拉起」，好处是走 gofs 的
优雅关闭流程。

同样**不要用 `go run`**：`os.Executable()` 会拿到临时文件，重执行它没有意义。

#### 卸载示例

`examples/uninstall/` 演示卸载那一半：

```bash
go build -o /tmp/gofs-uninstall-demo ./examples/uninstall
/tmp/gofs-uninstall-demo -root ./data -port 8080
```

它按**正确的顺序**列出卸载要做的事，并在启动时先把清单打出来（卸载是本服务
最不可逆的操作，动手之前先看清会删什么）：

1. 停服务 —— 反过来的话文件删了服务还在跑，处于「半死」状态：端口还占着、
   日志还在写，而你已经没有它的配置了；
2. 删注册项（systemd unit / launchd plist）并 `daemon-reload` —— 否则它开机
   还会被拉起来，而那时二进制已经没了；
3. 清配置目录（`keys.json` / `users.json` / `settings.json`）；
4. 删二进制（非 Windows；删正在运行的可执行文件是可行的，inode 会保留到
   进程退出）。

⚠️ **默认一个文件都不删**：步骤 2~4 的目标全部由开关决定
（`-unit` / `-purge-config` / `-remove-binary`），不给就只演示流程 ——
演示程序不该把你刚 `go build` 出来的东西删掉。

`-exit` 演示两条收尾路径，两者前端都能正确处理：

| 取值 | 行为 | 页面看到 |
| --- | --- | --- |
| `later`（默认） | 响应正常写完，进程随后退出 | 200 `{"ok":true}`，之后轮询确认它没再回来 |
| `now` | 回调里立刻 `os.Exit`，响应写不出去 | 连接被掐断（前端把断连当成功） |

`now` 那条特意用 `os.Exit` 而不是给自己发 SIGTERM：gofs 的 `Run` 装了 SIGTERM
处理器，会走优雅关闭把在途请求（包括当前这个）等完再退 —— 那样响应照样发得
出去，就演示不出「断连」这条路径了。代价是跳过优雅关闭，在乎在途传输的部署
应当用 `later`。

#### 多站点示例

`examples/sites/` 演示**多站点怎么配**。

⚠️ 注意这个与前两个不同：站点**不是扩展点**（不需要实现任何接口，库自带），
所以它演示的是接线，而不是实现。

```bash
go build -o /tmp/gofs-sites ./examples/sites
/tmp/gofs-sites -root ./data -site ./backup -site /srv/projects

# 只放开 /srv 下的目录可以在页面上新增；默认只允许主目录的父目录
/tmp/gofs-sites -root /srv/data -allow /srv ...

# 静态挂几个目录、不许页面上改
/tmp/gofs-sites -no-manage ...
```

它把三件容易配错的事摆在一起：

1. **主目录在 `/`、站点在 `/<标签>/`**（`WithRoots` 的第一个是主目录）；
2. **按站点分权限**：`uploader:upload123@/uploads:rw` —— 规则里的路径要
   **带上标签**，这正是从单根迁到多站点时最容易漏的一处（绑在 `/` 上的旧
   规则不会覆盖站点）。示例按第一个站点的目录名推导出这个规则；
3. **运行期可挂哪些目录**：`-allow` 对应 `Config.RootAllow`（用 `WithTune`
   设置），不给则默认只允许主目录的父目录；`-no-manage` 关掉页面上的增删。

配套测试（`examples/sites/main_test.go`）走的是**同一个 `build()`**（不是另抄
一份接线），用 httptest 直接驱动：各站点可取到正确内容、`uploader` 只能进自己
的站点、范围内可增可删而范围外 400、`-no-manage` 下接口返回 403 但静态站点
照常可用。

## 界面细节

行操作里的**「链接」**（以及预览弹窗底部的「复制链接」）会把文件的**绝对地址**
复制到剪贴板，可以直接发给别人：

```
https://your-host/docs/报告.docx
```

用绝对地址而不是相对路径 —— 复制出去的链接是给别人的，相对路径到了别人那里就断了。

- **开了鉴权时，链接本身不含凭据**，所以提示里会写明「对方需要登录后才能访问」。
- 复制优先用剪贴板 API，**失败时退回 `execCommand`**（纯 HTTP 部署、权限被拒、
  文档失焦都会让前者不可用）。
- 只读账号也有这个按钮：把地址发给别人跟写权限无关。

### 在线编辑的大小上限

**超过上限的文件不能编辑**，而且这个上限**可以在页面上改**，不用重启：

```
服务设置 → 在线编辑大小上限    默认 2 MiB
```

改完立刻生效：列表里的「编辑」入口跟着变，服务端也会按新值拒绝读写。

- 超限时「编辑」按钮**仍然显示但不可点**，并附一句原因（「超过 2.0 MiB」）——
  比直接隐藏更好，用户能知道为什么。
- 上限**服务端也强制**（`/fs/text` 的读写都查），不是只靠前端藏按钮；
  否则绕过去就能改一个几百 MB 的文件。
- 这一项**没有「不限制」**：打开文件要把整份内容读进内存，放开等于留个口子。
  启动参数 `--edit-max-size` 一直也是「必须为正整数」，两边语义必须一致。

## 界面细节

这些不是「有没有功能」的问题，而是「功能在不在用户眼前」的问题。逐条说明：

**① 拖拽上传要让用户看得见、也知道落到哪。**
只靠「拖到一半才出现的浮层」是不够的 —— 用户**开始拖之前**根本不知道这页支持拖拽。
所以桌面端有写权限时目录页常驻一块虚线投放区；文件拖进窗口后，再弹出全屏浮层。
**常驻区、拖拽浮层、上传弹窗、上传按钮的悬停提示**四处都会写明落点，
而且只有真的会归档时才追加「（按日期自动归档）」：

```
站在根目录（会归档）：
把文件或文件夹拖到这里，或点击选择文件
存入 /2026/09/28/（按日期自动归档）　·　单文件 ≤ 10.0 GiB      ← 整条可点

松开即可上传
存入 /2026/09/28/　·　3 项　·　单文件 ≤ 10.0 GiB               ← 拖拽浮层

存入：/2026/09/28/（按日期自动归档）　·　单文件上限：10.0 GiB    ← 上传弹窗


站在子目录 /docs（不归档，原地放）：
把文件或文件夹拖到这里，或点击选择文件
存入 /docs/　·　单文件 ≤ 10.0 GiB
```

手机端（`≤560px`）不常驻投放区：手机不能拖拽，而顶栏的「上传」就在同一屏，
再放一张占掉 70px 的虚线卡片只是重复。拖拽浮层仍然保留，外接键鼠时可用。

投放区没有额外的「选择文件 / 选择文件夹」按钮：整条都可点，文件夹上传走
顶栏上传按钮右侧的 caret →「上传文件夹」，或直接把文件夹拖进来。批量选择、
搜索结果出现、或目录为空时，投放区会自动收起，把空间让给当前任务
（空状态里已有上传 / 新建入口）。

拖拽浮层还会实时给出**本次拖进来的条目数**（一个文件夹算 1 项，
展开后的真实文件数在上传弹窗里显示）；松手或离开窗口后浮层立刻收起。
归档规则见上文「上传按年月日归档」，文件夹上传见「上传文件夹」。

**② 所有弹窗的底部统一。** 从前是每个弹窗各自拼按钮，间距、对齐、按钮顺序都不一致，
「确定」有时在左有时在右。现在统一走 `G.modalFoot()`：
底部区在正文之外（有独立分隔线与背景）、**取消恒在左、确认恒在右**，
危险操作（删除、放弃未保存的修改、取消上传上限）用**实心红按钮**。

**③ 上传速度与剩余时间。** 进度弹窗显示「已传 / 总量（百分比）　·　1.2 MiB/s　·　剩余 8 秒」。
速度用**指数平滑**（系数 0.35，采样间隔 ≥0.35s）算，而不是「已传字节 / 已耗时」——
后者在「先慢后快」时严重滞后，看着像卡住了；平滑系数是实测的折中（再大抖动明显，再小反应慢）。
速率没稳定到 4 KiB/s 以上之前不显示剩余时间，免得闪出一串离谱数字。

**④ 页脚说真话，但不复述权限。** 页脚改为实时渲染（在 `renderPerms` 里调用，
而不是启动时算一次）：左边是版本号，右边只显示**当前真实账号与可写性**，
以及会随目录变化的上传归档落点：

```
已登录 admin · 可读写　·　上传归档到 2026/09/28/
未登录 · 只读
无需登录 · 可读写          （服务本身没开鉴权时不提「登录」，避免困惑）

窄屏（≤560px）省掉装饰性的版本号：
admin · 可读写　·　上传归档到 2026/09/28/
```

「可上传 / 可删除 / 可在线编辑 / …」这一长串已经由顶栏按钮、行内操作和
账号芯片表达过，再抄一遍只会把页脚变成公告栏。完整的权限清单放在
账号芯片的 `title` 里（悬停可见），手机端也能从按钮显隐看出能力。
登录后不会再残留「只读模式」这类过期状态。

**⑤ 运行期服务设置。** 见上文「服务设置（运行期）」。

**⑥ 上传上限可改。** 同上；启动参数给默认值，页面上按需覆盖。

**⑦ 操作按钮用三组语义色。** 行内按钮带 `data-kind`，CSS 为每个类别定义独立变量
（定义在 `:root`，深色主题另有覆盖，不是散落各处的硬编码色值）。
早先是每个操作一个色相（蓝 / 靛 / 青 / 紫 / 青绿…），菜单看起来像调试标签；
现在收敛成「强调 / 中性 / 危险」三组：

| 分组 | `data-kind` | 变量 | 浅色取值 |
| --- | --- | --- | --- |
| 查看与编辑（打开 / 预览 / 下载 / 编辑） | `open` `preview` `download` `edit` | `--op-open` 等 | `var(--accent)` 蓝 |
| 整理与分享（内容 / 复制链接 / 分享链接 / 移动 / 重命名） | `list` `link` `share` `move` `rename` | `--op-list` / `--op-rename` | `var(--text-dim)` 中性灰 |
| 解压 | `unzip` | `--op-unzip` | `var(--zip)` 琥珀 |
| 删除 | `trash` | `--op-danger` | `var(--danger)` 红 |

「更多」菜单（手机端）里的图标复用同一批颜色。另外操作区的常态透明度从 `0.35`
提到可辨识的水平（触摸设备上恒为不透明），不用再靠 hover 才能看清。

**⑧ 顶部统计的准确性。** 统计区分**两个口径**，并在 `title` 里写明：

- 未选中时：`3 个目录 · 8 个文件 · 文件合计 1.2 MiB` —— 这是**整个目录**的规模。
  目录数与文件合计来自服务端全量统计（`dir_count` / `file_size`），
  **即使列表被截断也算得准**，并在末尾额外标注
  `已截断：该目录共 20000 项，仅列出前 20000 项`；
- 选中后：在这个口径**之前再叠加**一段
  `已选 2 项（1 个目录 · 1 个文件 · 34 KiB）　/　`，而不是把目录规模替换掉。

这样「选中几个文件想删掉」时，两个数字都能读到自己的意思。

**⑨ 长列表的表头与顶栏真的会吸顶。** 长目录滚动时顶栏留在顶部，表头贴在
顶栏下沿；进入批量选择后，表头自动让开吸顶的工具条（偏移由 JS 写入
`--table-head-top`，值 = 顶栏高度 + 工具条高度）。`.table-wrap` 用
`overflow: clip` 而不是 `hidden`：后者会建立滚动容器，表头的 sticky 就只在
那个不滚动的容器里生效。

这里还有一个容易忽略的前提：**`body` 不能固定成 `100%` 高**。body 同时是
flex 容器，内容会溢出到 body 盒子之外；body 只有一屏高时，顶栏 sticky 的
包含块也只到一屏，滚过一屏后整条顶栏会跟着滚走。现在由 `min-height:100vh`
撑开，内容自然增高。

**⑩ 读屏与键盘是一条闭环。** 列表补上了语义：表格带 `aria-label`、
表头都是 `scope="col"`，统计区用 `aria-live="polite"`（选择 / 搜索后结果
规模会被读出来），面包屑的当前层级带 `aria-current="page"`。站在根目录时，
「根目录」渲染成不可点的当前页，而不是一个点下去没反应的链接。

菜单也按「菜单」来用：顶栏下拉与行内「更多」打开即聚焦第一项，
↑/↓/Home/End 在项间移动，`Esc` 关闭并把焦点还给触发按钮
（`aria-expanded` 同步复位，读屏不会一直以为还开着）。搜索框按 `↓`
进入首条结果（空结果则聚焦空状态里的动作），首条结果按 `↑` 回到搜索框 ——
改词、看结果、再改词不必再 Tab 过一排顶栏控件。

传输进度不抢读屏：进度 toast 在进行中是 `role="progressbar"`
（`aria-valuenow` / `aria-valuetext` 跟着进度更新，可按需读取），
`aria-live` 关掉；完成或失败时才切回 `polite`，只播报一次最终结果 ——
否则每传一块就被念一遍，读屏用户没法用页面。设置页的监听地址与端口
收进默认折叠的「高级网络设置」，摘要直接写当前端点（`127.0.0.1:5000` /
`unix socket`），低频高风险项不必一直占着表单。

**⑪ 大目录分批渲染。** 首屏只创建前 200 行 DOM，底部显示
「已显示 200 / N 项」和「再显示 200 项」；追加时只 append 新行，不重建
已有行，滚动位置和已加载内容都保留。导航与搜索会把批次重置到 200。

统计、全选、打包、批量操作仍以 `state.entries` 的**完整结果集**为准，
不是只算已渲染的行 —— 所以点「全选」会连尚未显示的行一起选中，
工具条会如实显示总数；继续「再显示」时这些行会以选中状态出现。

选中集合包含未渲染行时，load-more 区域会写明「其中 N 项已选中但未显示」；
删除 / 移动 / 打包会二次确认并带上同样的提示。键盘焦点在「再显示」上
按 Enter 后不会丢；表格里按 End 会先补齐剩余批次，再聚焦真正的最后一行。

### 目录导航：地址栏与并发点击

目录切换是 `fetch` + `history.pushState` 做的（不整页跳转）。这里有两个
「只在特定条件下才暴露」的坑，都已修掉并被回归测试盯住。

**① 根目录的 URL 不能拼成 `//`。** 从前写的是 `pushState(..., fileURL(path) + '/')`，
而根目录的 `fileURL('/')` 本身就是 `'/'`，拼出来是 `'//'` —— 浏览器把它当
**协议相对 URL**（scheme-relative），解析成 `http:` 加一个空主机，于是：

```
Failed to execute 'pushState' on 'History':
A history state object with URL 'http:' cannot be created in a document with
origin 'http://127.0.0.1:5000' ...
```

它还在 `navigate` 的 `try` 里，异常被当成「打开目录失败」，`render()` 根本没执行 ——
**目录其实已经取回来了，却卡在原地并弹一个误导的错误**。
现在用一个 `dirURL()` 保证「恰好一个结尾斜杠」，并且地址栏更新单独包了 `try`：
**它只是锦上添花，任何原因失败都不该拖垮这次导航**。

**② 导航途中的点击不能被静默丢弃。** 从前是 `if (state.busy) return;`。
用户点「根目录」的那一刻，如果恰好有一次「上传完成后的列表刷新」在途
（很常见），这次点击就**白点了**：地址栏不动、列表不动、也没有任何提示。
现在改成**排队**：记下最后一次请求，等当前导航结束后补跑；
被后一次取代的那次会立刻以 `false` 结束，免得调用方一直等下去。

```js
const p1 = navigate('/docs');   // 在途
const p2 = navigate('/');       // 排队
const p3 = navigate('/docs');   // 取代 p2 → p2 立刻拿到 false
// 最终停在 /docs，p1/p3 为 true
```

排查这类问题可以在浏览器控制台打开 `window.__navDebug = true`，
每次导航都会打印目标路径与**调用来源**（含调用栈），比单步断点快得多。

## 与 dufs 的差异

| 项 | dufs | gofs |
| --- | --- | --- |
| 语言 | Rust | Go |
| 在线解压 | 仅支持目录打包下载 | 支持 zip / tar / tar.gz / gz 的解压、预览、单文件取出 |
| 解压进度 | — | SSE 实时推送 |
| 在线编辑 | 支持（简单文本框） | 支持，带行号、Markdown/HTML/JSON/XML 预览、摘要乐观锁、换行与 BOM 保留 |
| 上传密钥 | — | 支持，可限目录 / 设有效期 / 撤销，只存摘要 |
| 用户管理 | 仅命令行 `-a` | 命令行 + **页面上增删改**，密码只存 PBKDF2 摘要，落盘 users.json |
| 登录体验 | 浏览器原生 Basic 弹窗 | 应用内登录框（仍是 Basic 协议） |
| 上传归档 | — | 传到根目录时按 年/月/日 三级目录归档（子目录原地放），可自定义布局、可单次覆盖 |
| 文件夹上传 | — | 支持（选目录 / 拖目录），保留完整层级；带进度、可中途取消 |
| WebDAV | 支持 | 未实现（仅实现了 MKCOL / MOVE 等基础方法） |
| Digest 鉴权 | 支持 | 仅 Basic（支持明文密码） |
| 哈希密码 | 支持 `$6$` sha512-crypt | 未实现 |
| 配置文件 | 支持 YAML | 仅命令行与环境变量 |
| 依赖 | 多个 crate | 零第三方依赖 |

## 作为库使用

gofs 不只是个二进制 —— 根包 `github.com/xxl6097/gofs` 就是它的公开 API，
可以直接把文件服务嵌进自己的程序。

```bash
go get github.com/xxl6097/gofs
```

### 最短的一段

`Serve` 是 `New + Run + Close` 的快捷方式，阻塞到 ctx 被取消：

```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
defer stop()

err := gofs.Serve(ctx, "./data",
    gofs.WithPort(8080),
    gofs.WithAllowAll(),
)
```

### 自己管生命周期

想知道实际端口、想在启动后做别的事，就用 `New` + `Start`：

```go
srv, err := gofs.New(
    gofs.WithRoot("./data"),
    gofs.WithPort(0),                      // 0 = 由系统分配
    gofs.WithAuth("admin:123@/:rw"),
    gofs.WithPermissions(gofs.Permissions{
        Upload: true, Edit: true, Extract: true,
    }),
    gofs.WithTune(func(c *gofs.Config) {   // 逃生舱：改任意字段
        c.MaxConcurrent = 128
    }),
)
if err != nil {
    return err
}
defer srv.Close()

if err := srv.Start(); err != nil {       // 非阻塞
    return err
}
log.Printf("文件服务已就绪: %s", srv.URL())   // 端口 0 时在这里拿真实地址

<-ctx.Done()
shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
return srv.Shutdown(shutdownCtx)          // 等在途请求结束
```

### 只借用 HTTP 处理逻辑

已经有自己的 `http.Server` 时，取 `Handler()` 挂上去就行，不用调 `Start`：

```go
srv, err := gofs.New(
    gofs.WithRoot("./data"),
    gofs.WithPathPrefix("/files"),   // 要与挂载路径一致，否则页面链接会指错
)
if err != nil {
    return err
}
defer srv.Close()

mux := http.NewServeMux()
mux.Handle("/files/", srv.Handler())
mux.HandleFunc("/api/", myOwnAPI)
```

### 几个要点

- **默认只读**。`gofs.Default()` 不开上传、删除、编辑、解压 ——
  需要哪项就用 `WithAllowAll` 或 `WithPermissions` 显式打开。
- **默认无鉴权**。要账号密码用 `WithAuth("admin:123@/:rw")` 配规则。
  未启用鉴权时管理接口默认关闭；库方式要让匿名调用者管理服务，
  需把 `Config.AllowAnonymousAdmin` 显式设为 `true`。
- **库不装信号处理器**。什么时候退出由你通过 ctx 决定，
  上面例子里的 `signal.NotifyContext` 就是命令行入口在做的事。
- **配置会被校验**。`New` 内部会跑一次 `Normalize`，
  非法的压缩级别、端口、日期布局在构造时就报错，不会拖到运行期。
- **`Close` 不能省**。它负责写出上传密钥、关闭日志文件；
  `Shutdown` 只停 HTTP，不释放这些资源。
- **权限推断不复刻命令行**。命令行里「没写 `--allow-edit` 就跟随 `--allow-upload`」
  依赖「flag 是否被显式设置」，库里没有这个概念，`Permissions` 字段即最终值。
- 命令行那套语义（参数 + `GOFS_` 环境变量 + banner）也能整个复用：
  `gofs.RunCLI(ctx, args, os.Stdout, os.Stderr)`，`cmd/gofs/main.go` 就是这么写的。
- **`Run` 便捷入口不带默认口令**：每次启动随机生成管理员口令并打印一次，
  且只监听 `127.0.0.1`。需要固定账号或监听地址时用 `New` +
  `WithAuth` / `WithBind` 自己配。

- **编辑后未保存时，退出 / 右上角 ✕ 都会弹出确认框**（点取消改动仍在，点放弃才关闭）
- **刷新页面后登录态保持**（用户名不会退化成「匿名」，凭据失效时回到登录框）
- **打包按钮随选中变化**：「打包下载」↔「打包所选 (N)」，且点击时分别发出
  GET（全部）/ POST（带 picks 的所选）请求
- **手机端「更多」菜单**：每行都有该按钮、点开后菜单项与行内按钮一一对应
  （同一份操作定义）、点选后菜单关闭
- **页脚与统计准确**：页脚显示当前真实账号与可写性（以及会变化的上传归档落点），
  完整权限在账号芯片的 `title` 里（登录后不再显示「只读模式」）；
  统计同时给出目录数、文件数与合计大小，选中后再叠加「已选 N 项」
- **拖拽上传的可见性**：桌面端常驻投放区、拖拽浮层、上传弹窗三处都写明
  **文件会落到哪个目录**，并给出单文件上限；进度里带**上传速度**与剩余时间 / 总量。
  手机端不渲染常驻投放区（顶栏已有上传入口）
- **空状态给出下一步**：空目录直接给「上传文件 / 新建文件夹」，并收起表头、
  全选框与常驻投放区；搜索无结果给「清除搜索 / 改用精确搜索」，而不是只留一句灰字

  破坏性操作用实心红按钮
- **操作按钮的语义色**：每个动作带 `data-kind`，CSS 为 open / download / edit /
  unzip / list / rename / trash 定义颜色变量（不是硬编码）。行内只给主操作上色，
  其余动作在「更多」菜单里按图标颜色区分，避免整排彩色文字抢走文件名的注意力
- **字号与间距尺度**：`:root` 里用 `--fs-*`（11–22px 八档）与 `--space-*`
  （4–32px）统一字号和主要布局间距，减少半像素字号与随手值
- **服务设置面板**：能打开、能读到当前根目录与上传上限、给出可切换范围、
  单位下拉与「不限制」开关齐全
- **目录导航**：点目录名能进子目录（地址栏、面包屑、列表三者一致）、
  点「根目录」能回来且**没有报错**、地址栏链接不是协议相对 URL（`//…`）、
  复杂点：**导航途中的再次点击不会被丢掉**（队列里只留最后一次）
- **归档只在根目录生效**：站在根目录时三处提示都写日期目录并标注「按日期自动归档」、
  页脚显示「上传归档到 …」；进子目录后这些提示全部消失、投放区指向子目录本身
- **文件夹上传**：入口在顶栏上传按钮右侧的 caret →「上传文件夹」（左侧主按钮直接选文件），
  也可以直接把文件夹拖进来；
  目录输入框带 `webkitdirectory`、点按钮打开的是目录框而不是文件框；
  选目录后**发出的 PUT URL 保留了目录层级**；拖拽目录走
  `webkitGetAsEntry` 递归（含「`readEntries` 分批返回」这条必须循环取完的路径）
- **用户与权限**：入口只对管理员可见、启动参数的账号标「来自启动参数」且不可编辑、
  权限以胶囊逐条列出、匿名访问单独说明；新建表单（密码遮蔽 / 显示 / 随机生成、
  权限行增删）、**发出去的请求格式**（POST + 结构化 rules、编辑时不带 password）、
  删除前必须确认且用实心红按钮
- **顶栏「更多」折叠菜单**：主题 / 新建 / 设置 / 退出登录都在面板里且
  **没有被 `hidden` 掉**（折叠是布局、隐藏是权限，两件事不能混）、
  展开后 `aria-expanded=true`、再点一次 / 点面板外 / 按 Esc 三条关闭路径、
  点菜单项后自动收起、不会顺带留下别的弹窗
- **窄屏文案**：临时给 `matchMedia` 打桩模拟 560px 屏，断言统计换成
  `N 目录 · N 文件`、页脚去掉「已登录」且只留身份与归档落点；
  常驻投放区在手机端不渲染；还原之后长口径文案又回来（说明两套都活着，不是把一套删了）
- **跨模块接口完整性**（`window.GOFS` 的 33 个约定接口逐个校验）
- **确认弹窗的返回值语义**（点「确定」必须得到 `true`，点「取消」得到 `false`）

> **为什么值得单独测这些：** 有三类 bug 只在特定路径上出现，`go vet`
> 和接口测试都发现不了，用户只会反馈“按钮点了没反应”：
>
> 1. **权限快照** —— 权限对象在脚本加载时被做成快照，登录后没更新，
>    导致除「下载」「打开」外的**全部按钮消失**，看起来像功能没实现；
> 2. **接口漏暴露** —— 某个 `G.xxx` 忘了赋值，调用处直接抛异常；
> 3. **确认弹窗返回值竞态** —— 按钮回调先 `close` 再 `resolve`，
>    `onClose` 里的 `resolve(false)` 抢先定值，用户点「确定」也只拿到 `false`，
>    于是「强制覆盖」「撤销密钥」全部静默失效。

上手改这个测试脚本时有两个容易踩的坑（都是实测踩出来的）：

- **挑元素要挑「能覆盖这条断言」的那个**，不是「第一个匹配正则的元素」。
  比如预览按钮只对 md/json/xml/html 出现，如果碰巧挑到目录里唯一的
  `.txt`，就会误报「预览功能坏了」；
- **合成点击事件的 `cancelable` 必须显式给 `true`**。
  `new MouseEvent('click', {bubbles: true})` 的 `cancelable` 默认是 `false`，
  `preventDefault()` 会失效，jsdom 会真的去导航，看起来像「应用没拦住默认跳转」。

三个带勾选状态的选项，不再靠单按钮循环切换。桌面端（>820px）主题按钮只留
图标 + caret，把按钮文字省给更常用的动作；手机上它本来就在「更多」面板里，
那里保留文字（一整列都是文字时突然只剩图标反而难认）。

**折叠只改布局，不改可用性。** 被收进菜单的按钮 `hidden` 属性照旧由权限控制，
菜单项也会跳过没权限的；「更多」按钮本身带文字（不是光秃秃一个 `⋯`），
否则「功能入口」看起来就像消失了 —— 这类误判在这个项目里出现过不止一次。
三个关闭路径都有：再点一次、点面板外、按 Esc；换目录时自动收起。

**为什么断点是 820 而不是 560。** 「顶栏放不下」是按钮数量问题，不是屏宽问题：
561px 时旧版要 161px、768px 时要 111px，都是被按钮数量顶上去的。
所以折叠的断点跟「面包屑占整行」的 820px 对齐，820 与 821 之间只差 4px，没有断层。

> **别踩的坑**：`.btn.icon` 在触摸设备上被固定成 `40×40`，特异度是 `(0,2,0)` ——
> 光靠「写在后面」压不住它，`.more-toggle { width: auto }` 会被吃掉，
> 结果「更多」二字被挤没。必须写成 `.btn.more-toggle` 同级对抗。

**统计 / 页脚在窄屏换短句，而不是靠截断。** 例如
`3 个目录 · 8 个文件 · 文件合计 54 KiB` → `3 目录 · 8 文件 · 54 KiB`；
页脚去掉「已登录」，只留「admin · 可读写」和归档落点，完整能力在账号芯片里。
常驻投放区在手机端整个不渲染 —— 手机不能拖拽，顶栏也已经有上传入口，
再摆一张 70px 的虚线卡片只是重复。

判据是 `window.matchMedia('(max-width: 560px)')`，封装在 `app.js` 的 `isNarrow()`。
⚠️ jsdom 没实现 `matchMedia`，直接调会抛异常把整页逻辑带崩，所以必须判空，
缺失时按宽屏处理（文案更完整的那个分支）。

**操作入口收进「更多」菜单。** 每行只保留一个主操作和一个「更多」；手机上主操作
收成图标（带 `title` / `aria-label`），「更多」点开是贴着按钮展开的下拉菜单
（每项 ≥40px 高）。菜单里始终是完整动作列表 —— **所有宽度共用同一份操作定义**，
不会出现「桌面点得到、手机点不到」的功能差异。批量选择时工具栏按钮用
「打包 / 重命名 / 移动 / 删除」短标签，不再只剩四个无语义图标。

**触摸目标一律 ≥40px。** 顶栏图标按钮 32→40、操作按钮、勾选框（用 `label`
把整格变成可点区域）、品牌 logo、面包屑、文件名（加垂直留白）。
判据分两级：按钮类要求两个方向都够大，文字链接只要求高度
（`.env` 这种文件名天然很窄，强求宽度没意义）。
勾选列刻意**不**收窄：它的可点区域是整格，一收窄就掉到 40px 以下
（实测 38×42 被判为「按不准」）—— 4px 的表格宽度不值得用「点不中」去换。

**底部安全区。** 页脚与弹窗在 `≤560px` 时给 `env(safe-area-inset-bottom)`
留位，免得被 iPhone 的底部横条压住。

**根除三类只在触摸设备上出现的毛病：**

| 症状 | 原因 | 做法 |
| --- | --- | --- |
| 行内主操作只剩图标 | 窄屏隐藏文字标签，触摸设备没有 hover 提示 | 保留 `title` / `aria-label`，完整文字在「更多」菜单里；批量按钮保留短标签 |
| 整页横向溢出 60px | `.topbar-actions` 是 flex 项目，默认不缩到比内容窄，内部换行没机会生效 | 加 `min-width: 0` + 内部 `flex-wrap`（**所有宽度**都生效，见下） |
| 输入框一聚焦页面就放大 | iOS 对 `font-size < 16px` 的输入框会自动缩放，且很难缩回去 | 触摸设备下输入框与编辑器统一 16px |

改编辑器字号时**必须同步改行号栏**：两者共用 1.65 行高，只改一边会让行号与代码
逐行错开（`editor.js` 只用 `scrollTop` 同步滚动，没有硬编码行高，所以调字号是安全的）。

**顶栏按钮变多会撑破中等宽度。** 这条一开始只写在手机断点里 —— 当时只有 4 个按钮，
561px 以上一行放得下。加到 6 个（上传 / 文件夹 / 新建 / 密钥 / 用户 / 设置）之后，
**561px 与 900px 都溢出**（分别 37px / 45px）：`.topbar-actions` 在那些宽度下仍是
`flex: none`，绝不缩到比内容窄，于是把整页撑出横向滚动条。
所以「允许换行 + `min-width: 0`」已经提到**基础规则**里，不再挂在手机断点下 ——
顶栏放不下是按钮数量问题，不是屏宽问题。

**回归命令：**

```bash
make touch-sweep     # 12 个宽度 × 触摸模拟：无横向溢出 / 目标 ≥40px / 无半透明
make touch-modals    # 单独校验编辑器、操作菜单、服务设置面板里的按钮
```

### 表格布局回归（真浏览器）

上面两个测试都碰不到**渲染后的几何**：列宽够不够、内容有没有画到隔壁单元格上，
是 CSS 与 `table-layout` 决定的，jsdom 不做布局计算。所以另有一个用 CDP 直连
headless Chrome 的测量脚本：

```bash
# 终端 A：起一个带调试端口的 headless Chrome
make cdp

# 终端 B：扫一遍所有响应式断点
make layout-sweep          # 或单测一个宽度：make layout W=1280
```

每个宽度都会校验三件事，任一不过就退出码非 0：

1. **表头可见列数 == 数据行可见列数** —— 只给 `th` 加 `display:none` 而漏掉 `td`，
   `table-layout: fixed` 的列宽分配会整体错位（实测能把操作列从 196px 挤到 34px）
2. **操作按钮没有溢出自己的单元格** —— 溢出会直接画到「修改时间」列上
3. **按钮没有折行** —— 折行不覆盖，但行高会变大

加 `TOUCH=1`（或直接 `make touch-sweep`）时再补两条：**页面无横向溢出**、
**可点目标达到最小边长**、**可点元素不能是半透明**。

目标开了鉴权时用 `MEASURE_AUTH=user:pass make layout`。

两个额外开关（改动 UI 时很省事）：

```bash
# 想人眼复核排版，而不是只看数字
MEASURE_SHOT=/tmp/shot.png node scripts/measure-layout.mjs http://127.0.0.1:5001 1440 900

# 量弹窗内部的元素（编辑器 / 行操作菜单 / 服务设置面板）
MEASURE_OPEN=settings node scripts/measure-layout.mjs http://127.0.0.1:5001 375 812
```

背后的几条 CSS 约束（改动列宽前请先读）：

- 每行只有**主操作 + 更多**两个按钮，`.op-btn` 仍是 `flex: none`，不会被压缩。
- 列宽只需要按「两个按钮」算：

  | 视口 | 按钮形态 | `.col-ops` |
  | --- | --- | --- |
  | >1280px | 主操作带文字 + 「更多」 | 184px |
  | 641–1280px | 两个纯图标 | 112px |
  | ≤640px | 两个纯图标 | 112px |

  触摸设备按钮放大到 40px，两个按钮加间距与内边距共 108px，给到 112/128px。
- `collapseWrappedOps()` 仍保留「按实际宽度测量」的兜底：极端宽度下若两个按钮
  仍放不下，主操作会收起，但菜单里始终包含完整动作列表，不会丢功能。
- 名字列是 `width: auto`，把剩余宽度全吃掉 —— 所以「列宽够不够」看的是操作列
  自己的宽度，不是整行的空白。

> 历史教训：隐藏列时必须同时隐藏 `th` 与 `td` 的 `col-*` 类，否则
> `table-layout: fixed` 下表头列数与内容列数不一致，列宽会整体错位。
